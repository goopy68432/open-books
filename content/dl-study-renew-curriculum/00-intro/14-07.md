## 1. Bias-Variance Tradeoff (편향-분산 트레이드오프)

### 일상적 비유

> 과녁 맞히기 게임을 상상해 보자.
>
> - **Bias(편향)가 높다** = 과녁의 중심이 아니라 항상 왼쪽 위를 겨냥하는 것. 아무리 많이 쏴도 중심에 맞출 수 없다.
> - **Variance(분산)가 높다** = 중심을 겨냥하긴 하는데, 화살이 사방으로 흩어지는 것. 운이 좋으면 맞지만 일관성이 없다.
>
> 이상적인 사수는 bias도 낮고 variance도 낮아서, 화살이 중심 근처에 촘촘히 모인다.

```
       Bias 낮음 + Variance 낮음        Bias 높음 + Variance 낮음
       (이상적! 최고의 모델)            (체계적으로 틀림)

            ◎                              ○
           ◎◎◎                           ○○○
            ◎                              ○
         [과녁 중심]                    [과녁에서 벗어남]

       Bias 낮음 + Variance 높음        Bias 높음 + Variance 높음
       (평균은 맞지만 흩어짐)           (최악: 빗나가고 흩어짐)

          ◎     ◎                      ○        ○
              ◎                            ○
        ◎         ◎                  ○         ○
         [과녁 중심 근처]              [엉뚱한 곳에 흩어짐]
```

### 핵심 개념 분해

#### (1) Approximation Error (근사 오차) = Bias

**한 줄 정의**: "우리가 선택한 모델 종류가 정답을 표현할 수 있는가?"

**비유**: 직선(1차 함수)으로 원을 그리려는 것. 아무리 노력해도 직선으로는 원을 완벽히 그릴 수 없다. 이때 발생하는 오차가 Approximation Error이다.

```
  실제 데이터 패턴 (곡선)        직선 모델로 근사

       ╭──╮                        /
      /    \                      /
     /      \                    / ← 직선으로는 곡선을
    /        ╰──╮               /    표현할 수 없다!

    → 이 차이가 Approximation Error (Bias)
```

**수식 설명**:

```
Approximation Error = L_P(h*_H) - L_P(h*)
```

- `h*` : 세상에서 가능한 최고의 함수 (신이 만든 정답 함수)
- `h*_H` : 우리가 선택한 모델 클래스 H 안에서 가장 좋은 함수
- `L_P(...)` : 전체 데이터(모집단)에 대한 오차

**쉬운 해석**:
- `h*`는 "정답"이다. 세상 모든 데이터를 완벽히 설명하는 함수.
- `h*_H`는 "우리 모델이 낼 수 있는 최선의 결과"이다.
- 둘의 차이가 Approximation Error이다.
- 모델이 단순하면(예: 직선) → 이 오차가 크다.
- 모델이 복잡하면(예: 신경망) → 이 오차가 작다.

#### (2) Estimation Error (추정 오차) = Variance

**한 줄 정의**: "데이터가 충분한가? 학습이 제대로 되었는가?"

**비유**: 한국 전체 국민의 평균 키를 알고 싶은데, 농구선수 10명만 측정한 경우. 데이터가 편향되어 있고 부족해서 실제 평균과 다른 결과가 나온다.

```
  모델 클래스 H 안에서의 최적 함수 h*_H
  vs.
  실제 학습 데이터로 찾은 함수 h_S

  h*_H: 데이터가 무한히 많을 때 찾을 수 있는 최적 함수
  h_S : 한정된 학습 데이터 S로 실제 찾은 함수

  ┌─────────────────────────────────┐
  │  모델 클래스 H                    │
  │                                   │
  │    ★ h*_H (이론적 최적)           │
  │         ↕ Estimation Error        │
  │    ● h_S  (실제 학습 결과)        │
  │                                   │
  └─────────────────────────────────┘
```

**수식 설명**:

```
Estimation Error = L_P(h_S) - L_P(h*_H)
```

- `h_S` : 실제 학습 데이터 S로 훈련해서 얻은 모델
- `h*_H` : 무한한 데이터가 있었다면 얻을 수 있는 최적 모델
- 데이터가 적으면 → 이 오차가 크다 (분산이 높다)
- 데이터가 많으면 → 이 오차가 작다 (분산이 낮다)

#### (3) 총 오차 분해

```
총 오차 = Approximation Error + Estimation Error
         (모델이 충분히        (데이터가 충분히
          복잡한가?)             많은가?)

L_P(h_S) - L_P(h*) = [L_P(h*_H) - L_P(h*)] + [L_P(h_S) - L_P(h*_H)]
                       ─────────────────────   ─────────────────────────
                       Approximation Error      Estimation Error
                       (Bias, 편향)              (Variance, 분산)
```

**핵심 트레이드오프**:

```
  모델 복잡도 →

  높음 ┤
       │ ╲  Approx. Error        Estim. Error  ╱
  오   │   ╲  (Bias)               (Variance) ╱
  차   │     ╲                               ╱
       │       ╲                           ╱
  크   │         ╲      ╱─────╲          ╱
  기   │           ╲  ╱  총오차  ╲     ╱
       │            ╳             ╲  ╱
       │          ╱  ╲             ╳
  낮음 ┤        ╱      ╲─────────╱
       └──────────────────────────────→
         단순              복잡
         (직선)            (딥러닝)

  ← Bias 높음              Bias 낮음 →
  ← Variance 낮음          Variance 높음 →
```

| 모델 복잡도 | Approximation Error (Bias) | Estimation Error (Variance) | 총 오차 |
|-------------|---------------------------|----------------------------|---------|
| 너무 단순 | 높음 (패턴 못 잡음) | 낮음 (안정적) | 높음 |
| 적당함 | 적당함 | 적당함 | **최소** |
| 너무 복잡 | 낮음 (뭐든 표현 가능) | 높음 (과적합) | 높음 |

### 딥러닝에서의 의미

- **모델을 키우면** (레이어 추가, 뉴런 추가): Bias 감소, Variance 증가
- **데이터를 늘리면**: Variance 감소 (Bias는 변화 없음)
- **정규화를 추가하면**: Variance 감소 (Bias 약간 증가)
- 딥러닝이 특별한 이유: 매우 큰 모델도 적절한 기법을 쓰면 Variance를 제어할 수 있다!

### 연습문제

**Q1.** 다음 상황에서 Bias와 Variance 중 어떤 것이 문제인지 판단하시오.

(a) Training loss: 0.01, Test loss: 0.45
(b) Training loss: 0.40, Test loss: 0.42
(c) Training loss: 0.35, Test loss: 0.80

**풀이**:

(a) **Variance (Estimation Error) 문제**
- 훈련 오차(0.01)는 매우 낮은데 테스트 오차(0.45)가 높다.
- 모델이 훈련 데이터에 과적합(overfitting)되었다.
- 해결: 데이터 증가, 정규화, 드롭아웃 추가

(b) **Bias (Approximation Error) 문제**
- 훈련 오차(0.40)와 테스트 오차(0.42)가 모두 높다.
- 둘의 차이는 작으니 Variance는 괜찮지만, 전체적으로 성능이 낮다.
- 모델이 너무 단순해서 패턴을 못 잡는 것이다 (underfitting).
- 해결: 모델 크기 증가, 더 복잡한 구조 사용

(c) **둘 다 문제 (Bias + Variance)**
- 훈련 오차(0.35)도 높고 (Bias 문제), 테스트와의 차이(0.45)도 크다 (Variance 문제).
- 해결: 모델 구조 재설계, 데이터 증가, 하이퍼파라미터 튜닝

## 2. 과적합 (Overfitting)

### 일상적 비유

> **시험 공부에 비유하자.**
>
> - 기출문제 100개를 답까지 통째로 외운 학생이 있다.
> - 이 학생은 기출문제 시험에서 100점을 맞는다 (Training Error = 0).
> - 하지만 새로운 문제가 나오면 못 푼다 (Test Error = 높음).
> - 이 학생은 "이해"한 것이 아니라 "암기"한 것이다.
>
> 반대로, 개념을 이해한 학생은 기출문제 점수가 약간 낮을 수 있지만(예: 90점),
> 새로운 문제도 잘 풀 수 있다 (Test Error도 낮음).

```
  "암기형 학생" (과적합 모델)          "이해형 학생" (좋은 모델)

  기출(Train): 100점 ████████████      기출(Train): 92점 █████████▏
  실전(Test):   45점 ████▌             실전(Test):  88점 ████████▊

  → 기출-실전 차이: 55점 (과적합!)     → 기출-실전 차이: 4점 (일반화!)
```

### 핵심 개념

#### 오차의 종류 정리

```
┌──────────────────────────────────────────────────────────┐
│                                                          │
│  L_S(h_S): Training Error (훈련 오차)                    │
│  = 학습 데이터에서의 성능                                  │
│  = 기출문제 점수                                          │
│                                                          │
│  L_P(h_S): Test Error (테스트 오차, 일반화 오차)           │
│  = 본 적 없는 새로운 데이터에서의 성능                     │
│  = 실전 시험 점수                                         │
│                                                          │
│  L_P(h*_H): 모델 클래스 H의 이론적 최적 성능               │
│  = 이 모델 구조가 이론적으로 달성 가능한 최고 점수          │
│                                                          │
│  일반화 격차 (Generalization Gap):                        │
│  = L_P(h_S) - L_S(h_S)                                   │
│  = 테스트 오차 - 훈련 오차                                │
│  = 실전 점수 - 기출 점수의 차이                            │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

#### 가설 공간 |H|와 일반화의 관계

**가설 공간(Hypothesis Space) H란?**

모델이 표현할 수 있는 모든 함수들의 집합이다.

- 직선 모델의 H: 가능한 모든 직선 (기울기와 절편의 조합)
- 2차 함수 모델의 H: 가능한 모든 포물선
- 신경망의 H: 가능한 모든 가중치 조합으로 만들어지는 함수들

```
  |H| = 가설 공간의 크기 (모델이 표현할 수 있는 함수의 수)

  |H| 작음 (단순 모델)              |H| 큼 (복잡한 모델)
  ┌────────┐                       ┌──────────────────────┐
  │ h₁ h₂  │                       │ h₁ h₂ h₃ h₄ h₅ h₆  │
  │ h₃ h₄  │                       │ h₇ h₈ h₉ h₁₀ h₁₁   │
  └────────┘                       │ h₁₂ h₁₃ ... h₁₀₀₀  │
  선택지 적음                       └──────────────────────┘
  → 잘못된 것을 고를 확률 낮음      선택지 많음
  → 대신 정답이 없을 수도           → 잘못된 것을 고를 확률 높음
                                    → 대신 정답이 포함될 가능성 높음
```

**수식으로 보는 일반화 오차 상한**:

```
일반화 오차 ≤ 훈련 오차 + √(ln|H| / 2n)

여기서:
- |H|: 가설 공간의 크기 (모델 복잡도)
- n  : 학습 데이터의 수
- ln : 자연로그 (큰 수를 작게 만드는 함수)
```

**이 수식이 말하는 것**:

| 상황 | ln\|H\| / 2n | 일반화 오차 | 해석 |
|------|-------------|-----------|------|
| 모델 복잡 + 데이터 적음 | 큰 값 | 높음 | 과적합 위험! |
| 모델 단순 + 데이터 많음 | 작은 값 | 낮음 | 안전 |
| 모델 복잡 + 데이터 많음 | 적당 | 적당 | 딥러닝이 작동하는 영역 |

```
  일반화 오차의 변화 (모델 복잡도 증가에 따라)

  오차
   ▲
   │
   │  ╲                    ╱
   │    ╲  Training Error╱  ← Test Error
   │      ╲            ╱     (일반화 오차)
   │        ╲        ╱
   │          ╲    ╱
   │            ╲╱ ← Sweet Spot (최적 복잡도)
   │            ╱╲
   │          ╱    ╲
   │        ╱        ╲───── ← Training Error
   │      ╱                    (거의 0에 수렴)
   │    ╱
   └────────────────────────→ 모델 복잡도
     단순                복잡

     Underfitting       Overfitting
     (과소적합)          (과적합)
```

### 딥러닝에서의 의미

- 딥러닝 모델은 |H|가 **어마어마하게** 크다 (파라미터 수억 개).
- 전통 이론에 따르면 무조건 과적합해야 하는데... 실제로는 잘 동작한다!
- 이 "이상한" 현상을 설명하는 것이 바로 다음에 나오는 **Double Descent**이다.

### 연습문제

**Q2.** 가설 공간 |H| = 100이고 학습 데이터 n = 50일 때, 일반화 오차의 상한에서 복잡도 패널티 항 √(ln|H| / 2n)을 계산하시오.

**풀이**:

```
√(ln(100) / (2 × 50))
= √(4.605 / 100)
= √(0.04605)
= 0.2146

→ 복잡도 패널티 ≈ 0.21
→ 훈련 오차가 0.05라면, 일반화 오차 ≤ 0.05 + 0.21 = 0.26
```

**Q3.** 같은 모델(|H| = 100)에서 데이터를 n = 500으로 늘리면?

**풀이**:

```
√(ln(100) / (2 × 500))
= √(4.605 / 1000)
= √(0.004605)
= 0.0679

→ 복잡도 패널티 ≈ 0.07
→ 데이터 10배 증가 → 패널티가 0.21에서 0.07로 약 3배 감소!
→ 데이터가 많을수록 일반화가 좋아진다
```

## 3. Double Descent (이중 하강)

### 일상적 비유

> **요리사 비유**:
>
> - **초보 요리사** (모델 작음): 레시피 3개만 안다. 단순하지만 실수가 적다.
> - **중급 요리사** (모델 적당): 레시피 20개를 안다. 다양한 요리를 잘 만든다. 하지만 가끔 레시피를 섞어서 실패한다.
> - **고급 요리사** (모델 큼, 전통적 관점): 레시피 200개를 안다. 너무 많이 알아서 오히려 혼란스러워 실패한다 → **여기까지가 전통적 U자 커브**
> - **마스터 셰프** (모델 매우 큼, Double Descent): 레시피 10,000개를 안다. 워낙 많이 알아서 어떤 재료가 와도 직관적으로 최적의 요리를 만든다! → **이것이 Double Descent의 두 번째 하강**

### 핵심 개념

#### Classical Regime (전통적 U자 커브)

전통적인 머신러닝 이론에서는 모델 복잡도를 높이면 오차가 U자 형태를 그린다고 봤다.

```
  Test Error
      ▲
      │
  높음│ ●                           ●
      │   ●                       ●
      │     ●                   ●
      │       ●               ●
      │         ●           ●
      │           ●       ●
      │             ●   ●
      │               ● ← Sweet Spot
      │
  낮음│
      └────────────────────────────→ 모델 복잡도
        Underfitting  │  Overfitting
                   최적점

        [전통적 U-shaped curve]
```

#### Modern Regime (Double Descent)

하지만 현대 딥러닝에서는 모델을 더 크게 만들면 놀라운 일이 일어난다!

```
  Test Error
      ▲
      │
      │ ●                 ●
      │   ●             ●   ●
      │     ●         ●       ●
      │       ●     ●           ●
      │         ● ●               ●
      │          ●                  ●
      │     1st descent               ●
      │                                 ● ← 2nd descent!
      │                                   ●
      │                                     ● (더 좋아짐!)
      └──────────┼─────────────────────────→ 모델 복잡도
                 │
           Interpolation
           Threshold
           (보간 임계점)
```

#### Interpolation Threshold (보간 임계점)

**비유**: 연립방정식에서 미지수의 수가 방정식의 수와 같아지는 지점이다.

```
  데이터 포인트 수 = n (방정식의 수)
  모델 파라미터 수 = p (미지수의 수)

  p < n : 과소결정 (Under-determined)
          → 방정식이 더 많다. 모든 데이터를 완벽히 맞출 수 없다.

  p = n : 보간 임계점 (Interpolation Threshold)
          → 딱 맞다. 모든 데이터를 정확히 지나가는 함수를 찾을 수 있다.
          → 하지만 "간신히" 맞추는 거라 불안정하다 → 오차 최대!

  p > n : 과잉결정 (Over-determined)
          → 미지수가 더 많다. 여러 해가 존재한다.
          → 그 중 "가장 부드러운" 해를 선택할 수 있다 → 오차 감소!
```

```
  구체적 예시:

  데이터: (1,2), (3,5), (4,3)  → 3개의 점

  [p < n] 직선 (파라미터 2개):
  ──────────────────
       5 ┤       ●
       4 ┤      ╱
       3 ┤    ╱  ● ← 직선으로는 3점을 정확히 못 지남
       2 ┤  ● ╱
       1 ┤╱
         └──────────

  [p = n] 2차 함수 (파라미터 3개):
  ──────────────────
       5 ┤    ●
       4 ┤   ╱ ╲
       3 ┤  ╱   ● ← 3점을 딱 지나감 (보간)
       2 ┤●╱       하지만 구불구불할 수 있음
       1 ┤
         └──────────

  [p >> n] 10차 함수 (파라미터 11개):
  ──────────────────
       5 ┤    ●
       4 ┤   ╱ ╲
       3 ┤  ╱    ● ← 3점을 지나는 많은 함수 중
       2 ┤●╱        가장 부드러운 것을 선택 가능!
       1 ┤
         └──────────
```

```
  Test Error

      │ ●              ●
      │  ●            ● ●

      │      ● ●                ●
      │       ●                   ●
      │                             ●

         │       │      │

         │       │      │

    Regime     Regime    Descent
```

#### ① Skydiving Regime (스카이다이빙 영역)

```
┌─────────────────────────────────────────┐
│  특징: 모델이 커질수록 무조건 좋아짐     │
│                                          │
│  ● ← 시작                               │
│    ●                                     │
│      ●                                   │
│        ●                                 │
│          ●  ← 계속 하강!                 │
│                                          │
│  현실 예시: LLM (GPT, Claude 등)         │
│  - 파라미터를 10억 → 100억 → 1000억으로  │
│    늘리면 성능이 계속 좋아진다            │
│  - "Scaling Law"가 지배하는 영역         │
│  - 아직 interpolation threshold에        │
│    도달하지 않은 상태                     │
│                                          │
│  핵심: 모델을 키우기만 하면 된다!        │
│  (= 현재 LLM 패러다임)                  │
└─────────────────────────────────────────┘
```

```
┌─────────────────────────────────────────┐
│  특징: 전통적 bias-variance tradeoff     │
│                                          │
│  ●             ●                         │
│    ●         ●                           │
│      ●     ●                             │
│        ● ●                               │
│         ● ← sweet spot                   │
│                                          │
│  현실 예시: 전통적 ML (SVM, 결정트리 등) │

│  - 교차검증으로 최적 복잡도를 찾는다     │
│  - "적절한 정규화"가 핵심               │
│                                          │
│  핵심: 최적의 복잡도를 찾아야 한다!      │

```

```
│  - Interpolation threshold를 넘으면          │
│    오히려 성능이 좋아진다                     │
│  - 모델이 충분히 크면 "부드러운" 해를        │
│    찾을 여유가 생긴다                        │
│  - 암묵적 정규화(implicit regularization)    │
│    효과                                      │
│                                              │
│  핵심: 모델을 "충분히" 크게 만들어라!        │
│  (= 현대 딥러닝 패러다임)                    │
└─────────────────────────────────────────────┘
```

### 세 영역 비교 정리

| 속성 | Skydiving | U-shaped | Second Descent |
|------|-----------|----------|----------------|
| **대표 분야** | LLM | 전통 ML | Deep Learning (CNN 등) |
| **모델 크기** | 초거대 | 중소 | 대형 |
| **데이터 규모** | 초대규모 | 소~중규모 | 대규모 |
| **전략** | 무조건 키워라 | 최적점 찾아라 | 충분히 키워라 |
| **정규화** | 덜 중요 | 매우 중요 | 암묵적으로 발생 |
| **예시** | GPT-4, Claude | Random Forest, SVM | ResNet-1000, ImageNet |

### 딥러닝에서의 의미

1. **"과적합이 무서워서 모델을 작게 만든다"는 잘못된 직관일 수 있다.**
   - Double Descent에 따르면, 충분히 큰 모델은 오히려 일반화가 좋다.

2. **Early Stopping의 재해석**:
   - Interpolation threshold 근처에서 학습을 멈추면 최악의 성능이 될 수 있다.
   - 충분히 오래 학습시키는 것이 나을 수 있다.

3. **현대 딥러닝의 성공 비결**:
   - 모델을 매우 크게 만들고 (파라미터 >> 데이터)
   - SGD의 암묵적 정규화에 의존하여
   - Flat minimum을 찾아가게 한다 (Part B에서 자세히 설명).

### 연습문제

**Q4.** 다음 각 상황이 세 영역 중 어디에 해당하는지 판단하시오.

(a) 파라미터 1750억 개의 언어 모델을 3000억 개로 키웠더니 성능이 향상되었다.
(b) Random Forest의 트리 수를 100 → 500으로 늘렸더니 처음엔 좋아지다가 나빠졌다.
(c) ResNet-18 → ResNet-152로 바꿨더니, ResNet-50 즈음에서 성능이 나빠졌다가 ResNet-152에서 다시 좋아졌다.

**풀이**:

(a) **Skydiving Regime** - 초거대 LLM은 아직 interpolation threshold에 도달하지 않아서 키울수록 좋아진다.

(b) **U-shaped Regime** - 전통적 ML 모델에서 흔한 U자 커브. 최적 트리 수를 교차검증으로 찾아야 한다.

(c) **Second Descent Regime** - 딥러닝에서 관찰되는 전형적인 double descent. 중간 크기(ResNet-50)에서 피크를 찍고, 충분히 큰 모델(ResNet-152)에서 다시 좋아진다.

## 4. 모델 용량과 일반화

### 일상적 비유

> **가방(모델)과 짐(데이터)의 비유**:
>
> - **Relative Model Capacity**: 가방 크기 대비 짐의 양. 가방이 짐보다 훨씬 크면, 짐을 여유롭게 정리할 수 있다 (=일반화 좋음).
> - **Train-Test Bifurcation**: 같은 브랜드에서 산 가방 두 개가 있는데, 한 가방에 짐을 넣는 연습을 하고(train), 다른 가방에 실전으로 짐을 넣는 것(test). 연습과 실전의 성능 차이.
> - **Interpolation Threshold**: 가방이 짐과 딱 같은 크기인 순간. 짐을 억지로 구겨 넣을 수는 있지만, 가장 불안정한 상태.

### 핵심 개념

#### Relative Model Capacity (상대적 모델 용량)

```
  Relative Model Capacity = 모델 파라미터 수 / 데이터 수
                           = p / n

  p/n < 1 : Under-parameterized (파라미터 부족)
            → 모든 데이터를 외울 수 없다
            → Training Error > 0

  p/n = 1 : Interpolation Threshold (보간 임계점)
            → 딱 맞게 외울 수 있다
            → Training Error = 0 (갓 도달)
            → 가장 불안정한 지점!

  p/n > 1 : Over-parameterized (파라미터 과잉)
            → 데이터를 외우고도 남는다
            → 여유 파라미터로 "부드러운" 해를 선택
            → 의외로 일반화가 좋아짐!
```

```
  p/n (상대 용량) vs. Test Error

  Test Error
      ▲
      │
      │                ●
      │              ●   ●
      │            ●       ●
      │          ●           ●
      │        ●               ●
      │      ●                   ●
      │    ●                       ●
      │  ●                           ●
      │●                               ●
      └──────────┼─────────────────────→ p/n
        0        1.0
              (임계점)
    Under-        Over-
    parameterized parameterized
```

#### Train-Test Bifurcation (훈련-테스트 분기)

"Bifurcation"은 "갈림길"이라는 뜻이다. 모델이 커지면서 훈련 오차와 테스트 오차가 갈라지는 현상.

```
  오차
   ▲
   │
   │ ●──●──●                    ← Test Error (높게 유지 또는 상승)
   │         ╲  ●──●──●
   │          ╲╱        ╲●──●
   │          ╱╲             ──● ← Test Error (결국 하강)
   │    ●──●╱   ╲
   │  ●╱         ●──●──●──●──● ← Train Error (0으로 수렴)
   │ ●
   └─────────┼──────────────────→ 모델 복잡도
             │
        여기서 갈라진다!
        (Bifurcation Point)

   핵심 관찰:
   - Train Error는 모델이 커지면 계속 감소하여 0에 수렴
   - Test Error는 한번 올라갔다가(피크) 다시 내려온다
   - 갈라지는 지점이 interpolation threshold 근처
```

### 딥러닝에서의 의미

| 개념 | 실용적 의미 |
|------|-----------|
| Relative Model Capacity | 모델 크기를 데이터 대비로 생각해야 한다. 절대적 크기가 아니라 상대적 크기가 중요! |
| Train-Test Bifurcation | 훈련 오차가 0에 가까운데 테스트 오차가 높다면, interpolation threshold 근처일 수 있다. 모델을 더 키워볼 것! |
| Interpolation Threshold | 이 지점을 "넘어서" 모델을 키우면 오히려 좋아질 수 있다 |

### 연습문제

**Q5.** 데이터 10,000개로 학습하는 상황에서, 다음 모델들의 Relative Model Capacity를 계산하고 어떤 영역에 해당하는지 판단하시오.

(a) 선형 회귀, 파라미터 100개
(b) 작은 CNN, 파라미터 10,000개
(c) ResNet-50, 파라미터 2,500만 개

**풀이**:

(a) p/n = 100 / 10,000 = **0.01** → Under-parameterized (한참 부족). U-shaped regime에서 underfitting 쪽.

(b) p/n = 10,000 / 10,000 = **1.0** → Interpolation Threshold 근처! 가장 불안정. 성능이 나쁠 가능성.

(c) p/n = 25,000,000 / 10,000 = **2,500** → 극단적으로 Over-parameterized. Double descent의 두 번째 하강 영역. 적절한 학습 기법을 쓰면 오히려 일반화가 좋을 수 있다.

## 5. Estimation Error 분석

### 일상적 비유

> **지도 앱 비유**:
>
> - 네비게이션(모델)이 "서울 → 부산" 최적 경로를 찾아준다.
> - **이론적 최적 경로** (`h*_H`): 모든 도로 정보를 완벽히 안다면 찾을 수 있는 경로.
> - **실제 찾은 경로** (`h_S`): 내가 경험한 도로들(학습 데이터)만으로 찾은 경로.
> - **Estimation Error**: 이론적 최적 경로와 실제 경로의 차이.
> - 도로를 많이 경험할수록(데이터 많을수록) 실제 경로가 이론적 최적에 가까워진다.

### 핵심 개념 심화

```
  Estimation Error = L_P(h_S) - L_P(h*_H)

  이것을 더 직관적으로 쓰면:

  "실제 모델의 진짜 성능" - "이론적으로 가능한 최고 성능"

  ≈ L_P(h_S)  (테스트 오차가 곧 일반화 오차의 대부분)
```

**왜 `≈ L_P(h_S)` 인가?**

```
  L_P(h*_H)가 매우 작다고 가정하면:

  Estimation Error = L_P(h_S) - L_P(h*_H)
                   ≈ L_P(h_S) - (작은 값)
                   ≈ L_P(h_S)

  즉, 충분히 복잡한 모델을 사용한다면 (Approximation Error가 작다면),
  일반화 오차는 거의 전부 Estimation Error이다!
```

#### 모델 복잡도에 따른 Estimation Error 변화

```
  Estimation Error
      ▲
      │
      │                              ●
      │                           ●
      │                        ●
      │                     ●
      │                  ●
      │              ●
      │          ●
      │     ●
      │ ●
      └──────────────────────────────→ 모델 복잡도 (|H|)

  모델이 복잡해질수록 Estimation Error 증가!
  (가설 공간이 넓어지면 잘못된 함수를 고를 확률 증가)
```

```
  하지만 동시에...

  Approximation Error
      ▲
      │ ●
      │    ●
      │       ●
      │          ●
      │             ●
      │                ●
      │                   ●
      │                      ●────●────● (0에 수렴)
      └──────────────────────────────→ 모델 복잡도 (|H|)

  모델이 복잡해질수록 Approximation Error 감소!
```

```
  두 오차를 합치면 (전통적 관점):

  총 오차
      ▲
      │●                            ●
      │  ●                        ●
      │    ●                    ●
      │      ●                ●
      │        ●            ●
      │          ●        ●
      │            ●    ●
      │              ●● ← 최적점 (Sweet Spot)
      └──────────────────────────────→ 모델 복잡도

  하지만 Double Descent에서는 이 최적점을 넘어서도 좋아질 수 있다!
```

### 딥러닝에서의 의미

- 딥러닝에서는 **모델 복잡도가 엄청나게 크지만** Estimation Error가 예상보다 작다.
- 그 이유: **SGD의 암묵적 정규화** + **Flat Minima 선호** (다음 섹션에서 설명)
- 전통 이론의 상한(bound)이 너무 느슨(loose)해서 실제 현상을 잘 설명하지 못한다.

### 연습문제

**Q6.** 모델 A(파라미터 1,000개)와 모델 B(파라미터 1,000,000개)가 같은 데이터셋으로 학습했다. 다음 결과를 해석하시오.

| 모델 | Train Loss | Test Loss |
|------|-----------|-----------|
| A | 0.15 | 0.18 |
| B | 0.001 | 0.12 |

**풀이**:

- **모델 A**: Train-Test 차이 = 0.03 (Estimation Error 작음), 하지만 전체 오차가 높음 (0.15, 0.18). Approximation Error가 크다 → 모델이 너무 단순하다.

- **모델 B**: Train-Test 차이 = 0.119 (Estimation Error 더 큼), 하지만 전체 Test Loss는 더 낮다 (0.12 < 0.18). Approximation Error가 크게 줄어서 총 오차가 감소한 것이다.

- **결론**: Estimation Error가 증가하더라도 Approximation Error 감소량이 더 크면, 전체 성능은 향상된다. 이것이 딥러닝에서 큰 모델이 잘 작동하는 이유이다.

## 6. Flat Minima = Good Minima (평탄한 극소 = 좋은 극소)

### 일상적 비유

> **골프공과 계곡 비유**:
>
> - **Sharp Minimum (뾰족한 극소)**: 깊고 좁은 틈새에 골프공이 빠진 상태. 아주 조금만 건드려도 공이 튀어나온다. 불안정하다.
> - **Flat Minimum (평탄한 극소)**: 넓고 얕은 계곡에 공이 있는 상태. 약간 흔들어도 공이 계곡 안에 머문다. 안정적이다.
>
> 딥러닝에서:
> - "건드린다" = 테스트 데이터가 훈련 데이터와 약간 다르다
> - "안정적" = 새로운 데이터에서도 성능이 유지된다 (일반화)

```
  Sharp Minimum (나쁜 극소)         Flat Minimum (좋은 극소)

  Loss                              Loss
   ▲                                 ▲
   │                                 │
   │ ╲                 ╱             │
   │   ╲             ╱               │ ╲                       ╱
   │     ╲         ╱                 │   ╲                   ╱
   │       ╲     ╱                   │     ╲               ╱
   │         ╲ ╱  ← 뾰족!           │       ╲───────────╱ ← 평탄!
   │          V                      │        (넓은 바닥)
   └──────────────→ θ               └──────────────────────→ θ

   작은 θ 변화 → Loss 크게 변함      작은 θ 변화 → Loss 거의 안 변함
   → 일반화 나쁨!                    → 일반화 좋음!
```

### 왜 Flat Minima가 일반화에 좋은가?

```
  핵심 아이디어:

  Training 데이터로 학습  →  θ* 위치를 찾음
  Testing 데이터로 평가   →  θ* 근처에서 Loss를 측정

  하지만 Training 분포와 Testing 분포는 약간 다르다!
  이 차이 때문에 Testing의 Loss 함수는 Training과 약간 다르다:

  Sharp Minimum에서:
  ┌───────────────────────────┐
  │  Loss                     │
  │   │                       │
  │   │  T╲    ╱T             │
  │   │    ╲  ╱               │
  │   │  S╲╲╱╱S               │
  │   │    ╲╱ ← Training(S)   │
  │   │    │                  │
  │   │    θ*                 │
  │                           │
  │  S = Training function    │
  │  T = Testing function     │
  │  T가 S에서 약간 벗어남     │
  │  → Loss 차이가 크다!       │
  └───────────────────────────┘

  Flat Minimum에서:
  ┌───────────────────────────┐
  │  Loss                     │
  │   │                       │
  │   │T╲                ╱T   │
  │   │  ╲              ╱     │
  │   │ S╲──────────────╱S    │
  │   │   ╲────────────╱      │
  │   │    (넓은 바닥)         │
  │   │    θ*                 │
  │                           │
  │  T가 S에서 약간 벗어나도   │
  │  → Loss 차이가 작다!       │
  └───────────────────────────┘
```

### Flatness/Sharpness 측정: Hessian의 최대 고유값

**Hessian이 뭔가?** (수학 배경 없는 사람을 위한 설명)

```
  1단계: 기울기 (Gradient, 1차 미분)
  ─────────────────────────
  "현재 위치에서 어느 방향으로 내려가야 하는가?"

  산 위에 서 있을 때, 발밑의 경사가 기울기이다.
  기울기 = 0이면 평평한 곳 (극소점 또는 극대점).


  2단계: Hessian (2차 미분)
  ─────────────────────────
  "기울기가 얼마나 빠르게 변하는가?"

  기울기의 변화율이다. 곡면이 얼마나 휘어있는지를 나타낸다.


  3단계: Hessian의 고유값 (Eigenvalue)
  ─────────────────────────
  "각 방향으로 곡면이 얼마나 휘어있는가?"

  고유값이 크면 → 그 방향으로 급격히 휘어있다 (Sharp)
  고유값이 작으면 → 그 방향으로 완만하다 (Flat)
```

**수식**:

```
  Sharpness 측정 = λ_max(∇²L(θ))

  ∇²L(θ)  : Loss 함수의 Hessian (2차 미분 행렬)
  λ_max   : Hessian의 가장 큰 고유값

  의미: "가장 급격하게 변하는 방향의 곡률"

  λ_max가 크면 → Sharp minimum → 일반화 나쁨
  λ_max가 작으면 → Flat minimum → 일반화 좋음
```

**비유로 이해하기**:

```
  λ_max = "계곡에서 가장 가파른 벽의 기울기"

  Sharp Minimum:                    Flat Minimum:

  벽이 가파름 (λ_max 큼)           벽이 완만함 (λ_max 작음)

       │╲╱│                         ╲          ╱
       │  │                           ╲──────╱
       │  │ ← λ_max = 1000             ← λ_max = 0.1

  "좁은 틈새"                      "넓은 분지"
```

### Training Function vs Testing Function 관계

```
  ┌───────────────────────────────────────────────────┐
  │                                                     │
  │  Training Loss Function L_S(θ):                    │
  │  = 학습 데이터 S에 대한 손실                        │
  │  = 이 함수의 극소점이 학습의 결과 (θ*)              │
  │                                                     │
  │  Testing Loss Function L_P(θ):                     │
  │  = 전체 데이터 분포 P에 대한 손실                   │
  │  = 이 함수에서 θ*의 값이 실제 성능                  │
  │                                                     │
  │  두 함수의 관계:                                    │
  │  L_P(θ) ≈ L_S(θ) + 약간의 차이                    │
  │                                                     │
  │  Flat Minimum에서는:                               │
  │  L_P(θ*) ≈ L_S(θ*) ← 차이가 작다! (일반화 좋음)   │
  │                                                     │
  │  Sharp Minimum에서는:                              │
  │  L_P(θ*) >> L_S(θ*) ← 차이가 크다! (일반화 나쁨)  │
  │                                                     │
  └───────────────────────────────────────────────────┘
```

```
  구체적 시각화:

  Loss
   ▲
   │        Testing (L_P)
   │       ╱ ╲
   │      ╱   ╲              Testing (L_P)
   │     ╱     ╲            ╱              ╲
   │    ╱       ╲      ────╱────────────────╲───
   │   ╱  Training╲  ╱  Training              ╲
   │  ╱   (L_S)   ╲╱   (L_S)
   │ ╱              ╱╲───────────────────╱╲
   │╱                 ╲─────────────────╱
   └────────────────────────────────────────→ θ

     Sharp 영역                Flat 영역
     L_P - L_S = 크다!         L_P - L_S = 작다!
     (일반화 나쁨)              (일반화 좋음)
```

### 딥러닝에서의 의미

1. **모델 선택 기준**: 같은 Training Loss를 가진 두 모델 중 Flat Minimum에 도달한 모델이 더 좋다.
2. **Sharpness-Aware Minimization (SAM)**: Flat Minimum을 명시적으로 찾는 최적화 기법이 연구되고 있다.
3. **배치 크기와 Flatness**: 작은 배치 → Flat Minimum, 큰 배치 → Sharp Minimum (다음 섹션에서 설명).

### 연습문제

**Q7.** 두 모델 A, B가 모두 Training Loss = 0.01을 달성했다. Hessian의 최대 고유값이 다음과 같다.

- 모델 A: λ_max = 500
- 모델 B: λ_max = 2

어떤 모델이 일반화 성능이 더 좋을지 예측하고, 그 이유를 설명하시오.

**풀이**:

**모델 B가 일반화 성능이 더 좋다.**

이유:
- 모델 B의 λ_max = 2로, 모델 A의 λ_max = 500보다 훨씬 작다.
- λ_max가 작다 = Flat Minimum에 있다 = Loss landscape가 평탄하다.
- 평탄한 곳에서는 Training 함수와 Testing 함수의 차이가 작다.
- 따라서 Training Loss 0.01과 비슷한 Test Loss를 가질 가능성이 높다.

모델 A는 λ_max = 500으로 Sharp Minimum에 있어서, 비록 Training Loss는 0.01로 같지만, Test Loss는 훨씬 높을 가능성이 크다.

```
  모델 A (Sharp):  Train=0.01, Test≈0.30 (예상) → 일반화 격차 0.29
  모델 B (Flat):   Train=0.01, Test≈0.03 (예상) → 일반화 격차 0.02
```

## 7. 정규화 (Regularization)

### 일상적 비유

> **정규화 = 모델에게 "겸손하게 행동해!"라고 제약을 거는 것**
>
> - 시험 공부할 때 "기출문제만 외우지 말고 개념을 이해해!"라고 하는 것과 같다.
> - 모델이 훈련 데이터에 너무 맞추려고 극단적인 가중치를 사용하는 것을 막는다.

### (1) Weight Decay / L2 Regularization (가중치 감쇠)

#### 개념

```
  원래 Loss 함수:
  L(θ) = 예측과 정답의 차이

  L2 정규화를 추가한 Loss 함수:
  L_reg(θ) = L(θ) + λ × ||θ||²
                     ─────────────
                     정규화 항 (패널티)

  ||θ||² = θ₁² + θ₂² + θ₃² + ... + θₙ²
         = 모든 가중치의 제곱 합
         = "가중치가 얼마나 큰가?"

  λ (람다) = 정규화 강도
           = "페널티를 얼마나 강하게 줄 것인가?"
```

**비유**: 짐을 싸는데 "무거운 짐은 벌금!"이라는 규칙을 추가하는 것.

```
  가중치(짐)가 클수록 벌금이 커진다.
  → 모델이 "꼭 필요한" 가중치만 크게 유지하고,
  → 나머지는 0에 가깝게 줄인다.
  → 결과적으로 더 단순한 모델이 된다.
```

```
  시각화:

  정규화 없이 (과적합 위험)         L2 정규화 적용 (부드러운 곡선)

       ╭╮  ╭╮                          ╭──────╮
      ╱  ╲╱  ╲                        ╱        ╲
     ╱        ╲                      ╱            ╲
  ──╱          ╲──                ──╱                ╲──

  가중치가 큰 값 가능               가중치가 제한됨
  → 구불구불한 함수                 → 부드러운 함수
  → 훈련 데이터에 과적합            → 새 데이터에도 잘 작동
```

#### Weight Decay의 수학적 의미

```
  가중치 업데이트 (일반 SGD):
  θ_{t+1} = θ_t - η × ∇L(θ_t)

  가중치 업데이트 (Weight Decay 적용):
  θ_{t+1} = θ_t - η × ∇L(θ_t) - η × λ × θ_t
           = (1 - ηλ) × θ_t - η × ∇L(θ_t)
             ─────────
             이 부분이 "감쇠"!

  매 스텝마다 가중치가 (1 - ηλ) 비율로 줄어든다.
  → 그래서 "Weight Decay (가중치 감쇠)"라고 부른다!

  여기서:
  η (에타) = 학습률 (Learning Rate)
  λ (람다) = 정규화 강도
  ∇L(θ_t) = Loss의 기울기 (Gradient)
```

```
  λ 값에 따른 효과:

  λ = 0     : 정규화 없음. 원래 SGD와 동일.
  λ = 0.001 : 약한 정규화. 가중치를 조금씩 줄임.
  λ = 0.01  : 적당한 정규화. 일반적으로 많이 사용.
  λ = 0.1   : 강한 정규화. 가중치가 너무 작아져서 underfitting 위험.
  λ = 1.0   : 매우 강한 정규화. 거의 모든 가중치가 0에 수렴.
```

### (2) Dropout (드롭아웃)

#### 개념

```
  학습 중에 무작위로 뉴런을 "꺼버리는" 기법

  일반 네트워크:                    Dropout 적용:

  입력  ● ─── ● ─── ● ─── ● 출력   입력  ● ─── ● ─╳─ ╳ ─── ● 출력
        │ ╲╱  │ ╲╱  │ ╲╱  │              │ ╲╱  │      │ ╲╱  │
        ● ─── ● ─── ● ─── ●              ● ─── ╳ ─── ● ─── ●
        │ ╲╱  │ ╲╱  │ ╲╱  │              │ ╲╱  │ ╲╱  │      │
        ● ─── ● ─── ● ─── ●              ╳ ─── ● ─── ● ─╳─ ╳

  모든 뉴런 활성                    ╳ = 비활성화된 뉴런
                                    (확률 p로 무작위 선택)
```

**비유**: 조별 과제에서 매번 다른 팀원이 빠지는 상황.

```
  - 한 명이 빠져도 과제를 완성할 수 있어야 한다.
  - 따라서 각 팀원이 독립적으로 역할을 수행할 수 있어야 한다.
  - 특정 한 명에게 의존하는 것을 방지한다.

  뉴런 관점:
  - 특정 뉴런에 의존하는 것을 방지 (co-adaptation 방지)
  - 각 뉴런이 독립적으로 유용한 특성을 학습하게 만든다
  - 결과적으로 더 견고한(robust) 특성을 학습한다
```

#### Dropout의 작동 방식

```
  학습(Training) 시:
  ────────────────
  각 미니배치마다:
  1. 각 뉴런을 확률 p로 비활성화 (보통 p = 0.5)
  2. 나머지 뉴런으로만 forward pass
  3. 나머지 뉴런으로만 backward pass (가중치 업데이트)

  추론(Inference/Test) 시:
  ────────────────────
  1. 모든 뉴런을 활성화
  2. 대신 모든 가중치에 (1-p)를 곱함
     (학습 때 평균적으로 (1-p) 비율만 활성화되었으므로)

  예시 (p = 0.5):
  학습 시: 뉴런 50%만 사용, 가중치 원본
  추론 시: 뉴런 100% 사용, 가중치 × 0.5
```

```
  Dropout의 직관적 이해:

  ┌─────────────────────────────────────┐
  │  Dropout ≈ 앙상블 (Ensemble) 효과    │
  │                                      │
  │  매번 다른 뉴런이 꺼지므로,           │
  │  매번 "다른 서브네트워크"로 학습하는   │
  │  것과 같다.                          │
  │                                      │
  │  학습 1회: ●─●─╳─●  (서브넷 A)       │
  │  학습 2회: ●─╳─●─●  (서브넷 B)       │
  │  학습 3회: ╳─●─●─●  (서브넷 C)       │
  │  ...                                 │
  │                                      │
  │  추론 시: 모든 서브넷의 "평균"으로     │
  │  예측하는 효과!                       │
  │                                      │
  │  → 여러 모델의 평균 = 더 안정적       │
  │  → Variance 감소 → 일반화 향상       │
  └─────────────────────────────────────┘
```

### (3) SGD가 Flat Minima를 선호하는 이유

이것은 정규화 기법은 아니지만, SGD 자체가 **암묵적 정규화(Implicit Regularization)** 역할을 한다.

#### SGD vs. GD (Full Batch Gradient Descent)

```
  GD (전체 배치):
  ─────────────
  모든 데이터를 사용하여 기울기를 계산한다.
  → 정확한 기울기 → 정확한 방향으로 이동
  → 가장 가까운 극소점으로 "정밀하게" 수렴
  → Sharp Minimum에 빠질 수 있다!


  SGD (확률적 경사 하강):
  ─────────────────
  데이터의 일부(미니배치)만 사용하여 기울기를 계산한다.
  → 노이즈가 있는 기울기 → 약간 흔들리며 이동
  → Sharp Minimum에 빠지더라도 노이즈 때문에 탈출!
  → 결국 Flat Minimum에 정착한다!
```

```
  시각화:

  Loss Landscape
   ▲
   │
   │  ╲    ╱───╲         ╱───────────╲
   │    ╲╱       ╲     ╱               ╲
   │     Sharp    ╲  ╱                   ╲
   │     Minimum   ╲╱     Flat Minimum    ╲
   │                       (넓은 골짜기)
   └─────────────────────────────────────→ θ

   GD의 경로:  ●→→→→→→→●  (Sharp에 직행하여 갇힘)
                     ↓
   SGD의 경로: ●→↗→↘→→↗→●→↘→→→→→●  (흔들리다가 Flat에 정착)
                     (노이즈 때문에
                      Sharp에서 탈출!)
```

#### 배치 크기와 Flat/Sharp Minima

```
  작은 배치 (예: 32)                큰 배치 (예: 4096)
  ─────────────────                ─────────────────
  - 기울기의 노이즈가 크다          - 기울기의 노이즈가 작다
  - 많이 흔들린다                   - 적게 흔들린다
  - Sharp에서 탈출하기 쉽다         - Sharp에서 탈출하기 어렵다
  - Flat Minimum에 도달!           - Sharp Minimum에 갇힐 수 있다
  - 일반화 좋음                     - 일반화 나쁠 수 있음


  배치 크기 vs. 일반화 성능:

  일반화 성능
      ▲
  좋음│ ●
      │   ●
      │     ●
      │       ●
      │         ●
      │           ●
      │             ●
  나쁨│               ●
      └──────────────────→ 배치 크기
        32  64  256  4096
```

```
  왜 노이즈가 도움이 되는가?

  ┌─────────────────────────────────────────────┐
  │                                               │
  │  Sharp Minimum = 좁은 골짜기                   │
  │  → 노이즈(흔들림)가 골짜기보다 크면 탈출!       │
  │                                               │
  │   노이즈 크기: ████████████  (작은 배치)       │
  │   골짜기 너비: ███                             │
  │   → 노이즈 > 골짜기 → 탈출 성공!              │
  │                                               │
  │  Flat Minimum = 넓은 골짜기                    │
  │  → 노이즈가 골짜기보다 작으면 머무름            │
  │                                               │
  │   노이즈 크기: ████████████  (작은 배치)       │
  │   골짜기 너비: █████████████████████           │
  │   → 노이즈 < 골짜기 → 안정적으로 머무름!       │
  │                                               │
  └─────────────────────────────────────────────┘
```

#### 학습률과 Flat Minima

```
  학습률(η)이 크면:
  - 한 번에 많이 이동 → 더 많이 흔들림
  - Sharp Minimum에서 탈출하기 쉬움
  - Flat Minimum을 선호

  학습률(η)이 작으면:
  - 한 번에 조금 이동 → 적게 흔들림
  - Sharp Minimum에 갇힐 수 있음

  실무 팁:
  - 처음에는 큰 학습률로 시작 → Flat Minimum 영역으로 이동
  - 나중에 학습률을 줄임 → 그 영역 내에서 미세 조정
  - 이것이 Learning Rate Schedule의 원리!
```

### 정규화 기법 종합 비교

```
┌──────────────────┬────────────────────┬─────────────────────┐
│     기법          │    작동 방식        │     효과             │
├──────────────────┼────────────────────┼─────────────────────┤
│ L2 정규화         │ 가중치 크기에       │ 가중치를 작게 유지   │
│ (Weight Decay)   │ 벌금을 부과         │ → 단순한 모델       │
├──────────────────┼────────────────────┼─────────────────────┤
│ Dropout          │ 무작위로 뉴런       │ 앙상블 효과          │
│                  │ 비활성화            │ → 견고한 특성 학습   │
├──────────────────┼────────────────────┼─────────────────────┤
│ SGD 자체         │ 미니배치의          │ Flat Minimum으로     │
│ (암묵적 정규화)   │ 노이즈             │ 자연스럽게 수렴      │
├──────────────────┼────────────────────┼─────────────────────┤
│ 작은 배치 크기    │ 노이즈 증가        │ Sharp에서 탈출,      │
│                  │                    │ Flat에 정착          │
├──────────────────┼────────────────────┼─────────────────────┤
│ Data Augmentation│ 학습 데이터를       │ 다양성 증가          │
│ (데이터 증강)     │ 인위적으로 늘림     │ → Variance 감소     │
├──────────────────┼────────────────────┼─────────────────────┤
│ Early Stopping   │ 학습을 적절한       │ 과적합 방지          │
│ (조기 종료)       │ 시점에 중단         │ → Estimation Error  │
│                  │                    │   제어               │
└──────────────────┴────────────────────┴─────────────────────┘
```

### 딥러닝에서의 의미

1. **SGD의 암묵적 정규화가 딥러닝 성공의 핵심 비결 중 하나이다.**
   - 딥러닝 모델은 파라미터가 엄청나게 많지만, SGD가 자동으로 좋은(flat) 해를 찾아준다.
   - 이것이 Double Descent에서 큰 모델이 잘 작동하는 이유의 일부이다.

2. **정규화는 "모델 복잡도 제어"의 또 다른 방법이다.**
   - Bias-Variance 관점: 정규화 = Variance를 줄이는 대신 약간의 Bias를 추가.
   - 하지만 적절한 정규화는 총 오차를 줄인다.

3. **실무적 조합**:
   - Weight Decay + Dropout + 작은 배치 + 학습률 스케줄 = 강력한 일반화.

### 연습문제

**Q8.** 다음 상황에서 어떤 정규화 기법을 사용하면 좋을지 추천하시오.

(a) Training Loss = 0.01, Test Loss = 0.50 (심각한 과적합)
(b) 이미지 분류 모델인데 훈련 데이터가 5,000장뿐이다.
(c) 큰 배치(4096)로 학습하는데 일반화가 안 된다.

**풀이**:

(a) **Weight Decay + Dropout + Data Augmentation 모두 적용**
- 일반화 격차가 0.49로 매우 크므로 강력한 정규화가 필요하다.
- Weight Decay로 가중치를 제한하고, Dropout(p=0.5)으로 앙상블 효과를 주고, Data Augmentation으로 데이터 다양성을 늘린다.

(b) **Data Augmentation이 가장 효과적**
- 데이터가 절대적으로 부족하므로, 이미지 회전/반전/크기 조절 등으로 데이터를 인위적으로 늘리는 것이 가장 효과적이다.
- 추가로 Dropout과 Weight Decay도 함께 적용한다.
- Transfer Learning(사전학습 모델 활용)도 매우 효과적이다.

(c) **배치 크기를 줄이거나, Learning Rate Warmup 적용**
- 큰 배치는 Sharp Minimum에 빠지기 쉬우므로, 배치 크기를 256 정도로 줄인다.
- 배치 크기를 줄일 수 없다면, LARS/LAMB 같은 대형 배치 최적화 기법을 사용하거나, Learning Rate를 배치 크기에 비례하여 키우고 Warmup을 적용한다.

**Q9 (종합문제).** 다음 개념들의 관계를 설명하시오: Bias-Variance Tradeoff, Double Descent, Flat Minima, SGD.

**풀이**:

```
  ┌─────────────────────────────────────────────────────────┐
  │                                                           │
  │  1. Bias-Variance Tradeoff (전통 이론):                   │
  │     "모델이 커지면 Variance가 증가하여 과적합한다"          │
  │                                                           │
  │                    ↓ 하지만...                             │
  │                                                           │
  │  2. Double Descent (현대 관찰):                           │
  │     "모델이 '충분히' 커지면 오히려 일반화가 좋아진다"       │
  │                                                           │
  │                    ↓ 왜?                                   │
  │                                                           │
  │  3. Flat Minima (이론적 설명):                             │
  │     "Over-parameterized 모델은 Flat Minimum에              │
  │      도달할 수 있고, Flat Minimum은 일반화가 좋다"          │
  │                                                           │
  │                    ↓ 어떻게?                               │
  │                                                           │
  │  4. SGD의 암묵적 정규화:                                   │
  │     "SGD의 노이즈가 자동으로 Flat Minimum을 찾아준다"       │
  │     "작은 배치 + 적절한 학습률 → Flat으로 수렴"            │
  │                                                           │
  │  결론:                                                     │
  │  딥러닝 = 매우 큰 모델 + SGD → Flat Minimum → 좋은 일반화 │
  │  (전통 이론의 예측과 다르게, 큰 모델이 잘 작동하는 이유!)   │
  │                                                           │
  └─────────────────────────────────────────────────────────┘
```

**핵심 요약**:
- 전통 이론은 "적절한 크기의 모델을 찾아라"고 한다.
- 현대 딥러닝은 "충분히 큰 모델 + SGD가 알아서 좋은 해를 찾는다"고 한다.
- SGD가 Flat Minimum을 선호하기 때문에, 큰 모델에서도 일반화가 잘 된다.
- 이것이 딥러닝이 전통 이론의 예측과 달리 성공적인 핵심 이유이다.

# 핵심 용어 정리

| 용어 | 한국어 | 의미 |
|------|--------|------|
| Bias | 편향 | 모델 클래스의 표현 능력 한계에서 오는 오차 |
| Variance | 분산 | 제한된 데이터에서 오는 불안정성 |
| Approximation Error | 근사 오차 | 모델 클래스가 정답을 표현 못 해서 생기는 오차 |
| Estimation Error | 추정 오차 | 데이터 부족으로 최적 함수를 못 찾아서 생기는 오차 |
| Overfitting | 과적합 | 훈련 데이터에만 잘 맞고 새 데이터에 못 맞는 현상 |
| Underfitting | 과소적합 | 훈련 데이터에도 잘 못 맞는 현상 |
| Hypothesis Space | 가설 공간 | 모델이 표현 가능한 모든 함수의 집합 |
| Interpolation Threshold | 보간 임계점 | 파라미터 수 = 데이터 수인 지점 |
| Double Descent | 이중 하강 | 임계점을 넘으면 오차가 다시 감소하는 현상 |
| Sharp Minimum | 뾰족한 극소 | 좁고 깊은 극소점, 일반화 나쁨 |
| Flat Minimum | 평탄한 극소 | 넓고 평평한 극소점, 일반화 좋음 |
| Hessian | 헤시안 | 2차 미분 행렬, 곡면의 곡률을 나타냄 |
| λ_max | 최대 고유값 | Hessian의 가장 큰 고유값, sharpness 측정 |
| Weight Decay | 가중치 감쇠 | 가중치에 벌금을 부과하는 정규화 |
| Dropout | 드롭아웃 | 무작위로 뉴런을 비활성화하는 정규화 |
| Implicit Regularization | 암묵적 정규화 | SGD가 자연스럽게 수행하는 정규화 효과 |

# 최종 정리: 이 챕터에서 기억해야 할 5가지

```
┌────────────────────────────────────────────────────────────┐
│                                                              │
│  1. 총 오차 = Bias(모델 한계) + Variance(데이터 부족)        │
│     → 모델 크기와 데이터 양의 균형이 중요하다                 │
│                                                              │
│  2. 과적합 = Train 잘함 + Test 못함                          │
│     → |H|가 클수록 위험하지만, "충분히" 크면 괜찮다           │
│                                                              │
│  3. Double Descent: 모델을 충분히 키우면 오히려 좋아진다      │
│     → Skydiving(LLM) / U-shaped(전통ML) /                   │
│       Second-descent(딥러닝) 세 영역을 구분하라              │
│                                                              │
│  4. Flat Minimum = 좋은 일반화                               │
│     → λ_max(Hessian)으로 측정. 작을수록 평탄하고 좋다        │
│                                                              │
│  5. SGD + 작은 배치 = 자연스럽게 Flat Minimum을 찾는다       │
│     → 딥러닝 성공의 숨은 비결. 명시적 정규화와 함께 사용      │
│                                                              │
└────────────────────────────────────────────────────────────┘
```
