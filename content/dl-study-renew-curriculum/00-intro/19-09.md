## 1.1 시퀀스 데이터의 직관

### 세상은 순서로 가득하다

우리 주변의 데이터 대부분은 **순서(sequence)**가 중요하다.

```
┌──────────────────────────────────────────────────────────────────┐
│  시퀀스 데이터의 예시                                              │
│                                                                    │
│  언어:    "나는" → "학교에" → "간다"                                │
│           순서를 바꾸면? "간다 학교에 나는" → 의미가 달라짐!          │
│                                                                    │
│  음악:    도 → 레 → 미 → 파 → 솔                                   │
│           순서를 바꾸면? 전혀 다른 멜로디!                           │
│                                                                    │
│  주가:    1000 → 1050 → 1030 → 1100 → 1200                        │
│           순서가 곧 시간의 흐름!                                     │
│                                                                    │
│  DNA:     A → T → G → C → A → G                                   │
│           유전 정보의 순서가 생명을 결정!                            │
│                                                                    │
│  비디오:  프레임1 → 프레임2 → 프레임3 → ...                         │
│           순서가 동작을 만든다!                                      │
└──────────────────────────────────────────────────────────────────┘
```

### 시퀀스 vs 비시퀀스 데이터

```
비시퀀스 데이터 (순서 무관):
  - 사진 한 장: 픽셀의 위치는 중요하지만 "순서"는 아님
  - 환자 정보: [키=170, 몸무게=65, 나이=25] → 어떤 순서로 넣어도 같은 결과

시퀀스 데이터 (순서 필수):
  - 문장: "고양이가 쥐를 잡았다" ≠ "쥐가 고양이를 잡았다"
  - 음성: 각 시점의 음파가 순서대로 연결되어야 의미가 됨
```

**핵심 질문**: 신경망이 이 "순서"를 어떻게 기억하고 활용할까?

## 1.2 RNN의 기본 개념

### 비유: 독서하는 사람

일반 신경망(MLP)은 **사진을 보는 것**과 같다 — 한 번에 전체를 본다.
RNN은 **책을 읽는 것**과 같다 — 한 단어씩 읽으며 내용을 기억한다.

```
일반 신경망 (MLP):
  입력 전체를 한꺼번에 처리

  [단어1, 단어2, 단어3, 단어4] → [신경망] → 출력

  문제: 단어 순서 정보가 사라짐!

RNN (순환 신경망):
  한 단어씩 읽으며 "기억"을 업데이트

  단어1 → [RNN] → 기억₁
                      ↓
  단어2 → [RNN] → 기억₂  (기억₁ + 단어2를 합쳐서)
                      ↓
  단어3 → [RNN] → 기억₃  (기억₂ + 단어3를 합쳐서)
                      ↓
  단어4 → [RNN] → 기억₄  (기억₃ + 단어4를 합쳐서)
                      ↓
                    출력
```

### RNN의 핵심 아이디어

```
매 시점 t에서:

  새로운 기억(hₜ) = f(이전 기억(hₜ₋₁), 현재 입력(xₜ))

  직관적으로:
  ┌─────────────────────────────────────────┐
  │  지금까지 읽은 내용의 요약  +  방금 읽은 단어  │
  │          ↓                                     │
  │  업데이트된 요약 (= 새로운 기억)                │
  └─────────────────────────────────────────┘
```

### 비유: 전화 전달 게임

```
RNN = "전화 전달 게임" (Chinese Whispers)

  사람1 → 사람2 → 사람3 → ... → 사람100

  각 사람은:
  1. 앞 사람에게서 메시지를 받고 (이전 기억)
  2. 자기만의 정보를 추가하고 (현재 입력)
  3. 다음 사람에게 전달한다 (새로운 기억)

  문제: 100번째 사람에게 전달될 때 처음 메시지는?
        → 거의 사라진다! 😱
        → 이것이 "기울기 소실 문제"
```

## 1.3 기울기 소실 문제 (Vanishing Gradient Problem)

### 왜 RNN은 긴 문장을 못 기억할까?

```
문장: "프랑스에서 태어나고 자란 마리는 (...매우 긴 이야기...) 불어를 유창하게 한다"

사람: "프랑스" → 당연히 "불어" 예측 가능!
RNN:  "프랑스"라는 정보가 너무 오래 전이라... 기억이 희미해짐

시각적으로:

  "프랑스" ─→ [기억] ─→ [기억] ─→ [기억] ─→ ... ─→ [기억] ─→ "불어" 예측
              ████      ███░      ██░░      ...      ░░░░
              100%       75%       50%       ...       ~0%

  → 기억이 점점 옅어진다! (= 기울기가 소실된다)
```

### 수학적 직관 (곱셈의 반복)

```
기울기 소실의 본질: 1보다 작은 수를 계속 곱하면?

  0.9 × 0.9 × 0.9 × 0.9 × 0.9 × ... (50번)
  = 0.9^50
  = 0.00515...  ← 거의 0!

  반대로, 1보다 큰 수를 계속 곱하면?
  1.1 × 1.1 × 1.1 × ... (50번)
  = 1.1^50
  = 117.39  ← 폭발!

  RNN의 역전파에서 정확히 이런 일이 발생한다.

  기울기 소실: 먼 과거의 정보를 학습할 수 없다
  기울기 폭발: 학습이 불안정해진다
```

## 1.4 LSTM / GRU: 게이트로 기억 관리하기

### LSTM: 장단기 기억 네트워크

**비유: 노트 필기하는 학생**

```
일반 RNN = 머릿속으로만 기억하는 학생
  → 수업이 길어지면 처음 내용을 잊어버림

LSTM = 노트에 필기하는 학생
  → 중요한 건 노트에 적고, 불필요한 건 지우고, 필요할 때 꺼내 봄
```

### LSTM의 3가지 게이트 (시각 가이드)

```
┌─────────────────────────────────────────────────────────────┐
│                    LSTM의 3개 게이트                          │
│                                                               │
│  ① 잊기 게이트 (Forget Gate) 🚮                              │
│     "이전 기억 중 뭘 버릴까?"                                  │
│                                                               │
│     예: "어제 날씨가 맑았다. 오늘은 비가 온다."                │
│     → "어제 맑았다"는 이제 불필요 → 잊기!                      │
│                                                               │
│     fₜ = σ(Wf·[hₜ₋₁, xₜ] + bf)                              │
│     출력: 0(완전 잊기) ~ 1(완전 기억)                          │
│                                                               │
│  ② 입력 게이트 (Input Gate) 📝                               │
│     "새로운 정보 중 뭘 저장할까?"                              │
│                                                               │
│     예: "오늘은 비가 온다" → "비" 정보를 저장!                  │
│                                                               │
│     iₜ = σ(Wi·[hₜ₋₁, xₜ] + bi)                              │
│     출력: 0(저장 안 함) ~ 1(전부 저장)                         │
│                                                               │
│  ③ 출력 게이트 (Output Gate) 📤                              │
│     "기억한 것 중 뭘 내보낼까?"                                │
│                                                               │
│     예: "우산" 관련 질문이면 "비" 기억을 출력!                  │
│                                                               │
│     oₜ = σ(Wo·[hₜ₋₁, xₜ] + bo)                              │
│     출력: 0(출력 안 함) ~ 1(전부 출력)                         │
└─────────────────────────────────────────────────────────────┘
```

### LSTM 정보 흐름 시각화

```
시점 t에서의 LSTM 동작:

                    셀 상태 (장기 기억 = "노트")
  Cₜ₋₁ ──────[×잊기]──────[+입력]────────────→ Cₜ
                ↑              ↑                  │
            잊기 게이트    입력 게이트         [출력 게이트]
                ↑              ↑                  │
                └──── [hₜ₋₁, xₜ] ────┘            │
                                                   ↓
                                                  hₜ (출력)

  핵심: 셀 상태(C)라는 "고속도로"가 있어서
        정보가 변형 없이 오래 전달될 수 있다!
        (= 기울기 소실 문제 해결!)
```

### GRU: LSTM의 경량 버전

```
┌─────────────────────────────────────────────────┐
│  GRU vs LSTM 비교                                │
│                                                   │
│  LSTM: 게이트 3개 (잊기, 입력, 출력)              │
│  GRU:  게이트 2개 (리셋, 업데이트)                │
│                                                   │
│  GRU의 핵심 아이디어:                             │
│  "잊기와 입력을 하나로 합치자!"                    │
│                                                   │
│  업데이트 게이트 (z):                             │
│    z가 1이면 → 이전 기억을 100% 유지 (잊기 X)     │
│    z가 0이면 → 새 정보로 100% 교체 (전부 잊기)    │
│    → 잊기와 입력을 하나의 게이트로 처리!           │
│                                                   │
│  리셋 게이트 (r):                                 │
│    이전 기억을 새 후보 계산에 얼마나 반영할지       │
│                                                   │
│  장점: 파라미터 수가 적어 학습이 빠르다             │
│  성능: LSTM과 대부분의 작업에서 비슷하다            │
└─────────────────────────────────────────────────┘
```

### RNN vs LSTM vs GRU 한눈에 비교

```
┌──────────┬──────────┬──────────┬──────────┐
│          │   RNN    │   LSTM   │   GRU    │
├──────────┼──────────┼──────────┼──────────┤
│ 게이트수  │   0개    │   3개    │   2개    │
│ 파라미터  │   적음   │   많음   │   중간   │
│ 학습속도  │   빠름   │   느림   │   중간   │
│ 장기의존  │   약함   │   강함   │   강함   │
│ 구조복잡  │   단순   │   복잡   │   중간   │
│ 적합작업  │ 짧은시퀀스│ 긴시퀀스 │ 범용     │
└──────────┴──────────┴──────────┴──────────┘
```

## 1.5 어텐션: "되돌아보기"의 힘

### 비유: 시험 치는 학생

```
RNN 방식 (어텐션 없음):
  교과서를 처음부터 끝까지 한 번 읽고, 책을 덮고, 시험을 본다.
  → 마지막에 읽은 내용만 기억남!

어텐션 방식:
  시험 중에 교과서를 다시 펼쳐볼 수 있다!
  → "이 문제는... 3장 내용이 중요하니까 3장을 집중해서 보자!"
  → 문제마다 관련 있는 부분에 "집중(attend)"한다
```

### 어텐션의 직관

```
번역 예시: "나는 고양이를 사랑한다" → "I love cats"

"I"를 생성할 때:
  "나는"에 집중! ████████████  (가중치: 0.9)
  "고양이를"     ██            (가중치: 0.05)
  "사랑한다"     ██            (가중치: 0.05)

"love"를 생성할 때:
  "나는"         ██            (가중치: 0.05)
  "고양이를"     ██            (가중치: 0.05)
  "사랑한다"에 집중! ████████████  (가중치: 0.9)

"cats"를 생성할 때:
  "나는"         ██            (가중치: 0.05)
  "고양이를"에 집중! ████████████  (가중치: 0.9)
  "사랑한다"     ██            (가중치: 0.05)

→ 매 출력 단어마다 입력의 어디를 볼지 "선택"한다!
```

## 2.1 Self-Attention 단계별 이해

### 핵심 질문: "나 자신에게 질문하기"

일반 어텐션은 "번역할 때 원문을 되돌아보는 것"이었다면,
**Self-Attention**은 "같은 문장 안에서 서로를 참조하는 것"이다.

```
문장: "그 동물은 길을 건너지 않았다. 왜냐하면 그것은 너무 피곤했기 때문이다."

"그것"이 가리키는 것은?
→ "그 동물" (사람은 자연스럽게 알지만, 컴퓨터는?)

Self-Attention이 하는 일:
  "그것" → 문장 내 모든 단어와의 관련성을 계산

  "그것" ↔ "그"       : 관련성 높음 ████████
  "그것" ↔ "동물"     : 관련성 높음 ████████████
  "그것" ↔ "은"       : 관련성 낮음 ██
  "그것" ↔ "길을"     : 관련성 낮음 █
  "그것" ↔ "건너지"   : 관련성 낮음 █
  ...

  → "그것" = "동물"이라는 것을 학습!
```

### Query, Key, Value 직관

```
비유: 도서관에서 책 찾기

  ┌─────────────────────────────────────────────────────┐
  │  Query (질문):  "나 이런 정보가 필요해!"              │
  │    = 현재 단어가 다른 단어에게 던지는 질문              │
  │                                                       │
  │  Key (태그):    "나는 이런 정보를 가지고 있어!"         │
  │    = 각 단어가 자신을 소개하는 태그                     │
  │                                                       │
  │  Value (내용):  "실제로 내가 전달할 정보야!"            │
  │    = 매칭되었을 때 실제로 전달되는 정보                  │
  └─────────────────────────────────────────────────────┘

  과정:
  1. Query와 모든 Key를 비교 (내적 = 유사도 계산)
  2. 유사도가 높은 Key에 높은 가중치 부여 (Softmax)
  3. 가중치에 따라 Value를 가중 평균

  도서관 비유:
  1. "딥러닝 입문서 있나요?" (Query)
  2. 사서가 모든 책의 태그(Key)를 확인
  3. 관련 책(Value)을 관련도 순으로 추천
```

### Self-Attention 계산 5단계

```
입력 문장: "I love cats" (3개 단어)

각 단어의 임베딩 벡터:
  x₁ = [1, 0, 1, 0]  ("I")
  x₂ = [0, 1, 0, 1]  ("love")
  x₃ = [1, 1, 0, 0]  ("cats")

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Step 1: Q, K, V 생성 (학습 가능한 가중치 행렬로 변환)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Q = X · Wq    (각 단어가 "질문"을 만듦)
  K = X · Wk    (각 단어가 "태그"를 만듦)
  V = X · Wv    (각 단어가 "내용"을 준비)

  Wq, Wk, Wv는 학습을 통해 최적화되는 행렬!

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Step 2: 유사도 점수 계산 (Q·Kᵀ)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Score = Q · Kᵀ

           Key_I  Key_love  Key_cats
  Q_I    [  4.0,    1.0,     2.0  ]    ← "I"가 각 단어와 얼마나 관련?
  Q_love [  1.0,    5.0,     3.0  ]    ← "love"가 각 단어와 얼마나 관련?
  Q_cats [  2.0,    3.0,     6.0  ]    ← "cats"가 각 단어와 얼마나 관련?

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Step 3: 스케일링 (√dₖ로 나누기)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Scaled Score = Score / √dₖ

  왜? 차원(dₖ)이 크면 내적 값이 커져서
      softmax가 극단적인 값(0 또는 1)을 내놓게 됨
      → 학습이 어려워짐
      → √dₖ로 나눠서 적절한 범위로 조정!

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Step 4: Softmax로 어텐션 가중치 계산
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Attention Weights = softmax(Scaled Score)

           I      love    cats
  "I"    [0.75,   0.05,   0.20]    ← "I"는 자기 자신에 75% 집중
  "love" [0.05,   0.70,   0.25]    ← "love"는 자기 자신에 70% 집중
  "cats" [0.10,   0.20,   0.70]    ← "cats"는 자기 자신에 70% 집중

  각 행의 합 = 1.0 (확률 분포!)

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Step 5: 가중 평균으로 최종 출력
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Output = Attention Weights · V

  "I"의 출력    = 0.75×V_I + 0.05×V_love + 0.20×V_cats
  "love"의 출력 = 0.05×V_I + 0.70×V_love + 0.25×V_cats
  "cats"의 출력 = 0.10×V_I + 0.20×V_love + 0.70×V_cats

  → 각 단어가 문맥을 고려한 새로운 표현을 얻음!
```

### 수식 한 줄 정리

```
Attention(Q, K, V) = softmax(QKᵀ / √dₖ) · V

  Q: 질문 행렬 (무엇을 찾고 있는가?)
  K: 키 행렬 (무엇을 제공할 수 있는가?)
  V: 값 행렬 (실제 제공하는 정보)
  dₖ: Key 벡터의 차원 (스케일링 용도)
```

## 2.2 Multi-Head Attention

### 왜 여러 개의 "머리"가 필요할까?

```
비유: 영화를 여러 관점에서 보기

  Head 1 (문법 담당): "주어-동사-목적어 관계를 본다"
    "고양이가 쥐를 잡았다"
     ───주어───  ──목적어──  ──동사──

  Head 2 (의미 담당): "의미적 연관성을 본다"
    "사과는 빨간색이고, 바나나는 노란색이다"
     ──과일──  ──색──       ──과일──  ──색──

  Head 3 (거리 담당): "가까운 단어 관계를 본다"
    "매우 아름다운 꽃"
     ──수식──  ──수식대상──

  Head 4 (장거리 담당): "먼 단어 관계를 본다"
    "처음에 시작한 프로젝트가 (...) 결국 성공했다"
     ────────────── 장거리 연결 ──────────────

  → 각 Head가 다른 관점에서 문장을 분석!
  → 모든 Head의 결과를 합치면 풍부한 이해!
```

### Multi-Head Attention 구조

```
입력 X
  │
  ├──→ Head 1: Attention(XWq₁, XWk₁, XWv₁) → Z₁
  ├──→ Head 2: Attention(XWq₂, XWk₂, XWv₂) → Z₂
  ├──→ Head 3: Attention(XWq₃, XWk₃, XWv₃) → Z₃
  ├──→ ...
  └──→ Head h: Attention(XWqₕ, XWkₕ, XWvₕ) → Zₕ

  Concat(Z₁, Z₂, ..., Zₕ) · Wo → 최종 출력

  핵심:
  - 각 Head는 독립적인 Wq, Wk, Wv를 가짐
  - 각 Head의 차원 = d_model / h  (예: 512/8 = 64)
  - 전체 계산량은 단일 Head와 거의 동일!
```

## 2.3 위치 인코딩 (Positional Encoding)

### 문제: 트랜스포머는 순서를 모른다!

```
RNN: 단어를 순서대로 처리하므로 자연스럽게 순서 정보가 있음
트랜스포머: 모든 단어를 동시에 처리 → 순서 정보가 없음!

  "고양이가 쥐를 잡았다"  ←  트랜스포머에게는
  "쥐를 고양이가 잡았다"  ←  이것과 구별이 안 됨!

  해결: 각 위치에 고유한 "위치 번호표"를 붙여주자!
```

### 사인/코사인 위치 인코딩

```
아이디어: 각 위치에 고유한 패턴의 벡터를 더해준다

  PE(pos, 2i)   = sin(pos / 10000^(2i/d))
  PE(pos, 2i+1) = cos(pos / 10000^(2i/d))

  시각화 (각 위치의 인코딩 패턴):

  위치0: ████░░░░████░░░░████░░░░  (특정 주파수 패턴)
  위치1: ░████░░░░████░░░░████░░░  (약간 이동)
  위치2: ░░████░░░░████░░░░████░░  (더 이동)
  위치3: ░░░████░░░░████░░░░████░  (더 더 이동)

  → 각 위치가 고유한 "지문"을 가짐!
  → 상대적 거리도 계산 가능! (사인/코사인의 수학적 성질)

  단어 임베딩 + 위치 인코딩 = 최종 입력
  [의미 정보]  +  [순서 정보]   = [의미 + 순서]
```

## 2.4 인코더-디코더 아키텍처

### 전체 트랜스포머 구조

```
원본 트랜스포머 ("Attention Is All You Need", 2017)

┌─────────── 인코더 (Encoder) ───────────┐  ┌─────────── 디코더 (Decoder) ───────────┐
│                                         │  │                                         │
│  입력: "나는 학생입니다"                  │  │  출력: "I am a student"                  │
│           │                              │  │           │                              │
│    [입력 임베딩 + 위치 인코딩]            │  │    [출력 임베딩 + 위치 인코딩]            │
│           │                              │  │           │                              │
│  ┌────────────────────┐  ×N             │  │  ┌────────────────────┐  ×N             │
│  │  Multi-Head        │                 │  │  │  Masked Multi-Head │                 │
│  │  Self-Attention    │                 │  │  │  Self-Attention    │                 │
│  │  + Add & Norm      │                 │  │  │  + Add & Norm      │                 │
│  │                    │                 │  │  │                    │                 │
│  │  Feed Forward      │                 │  │  │  Multi-Head        │                 │
│  │  Network           │                 │  │  │  Cross-Attention   │←── 인코더 출력   │
│  │  + Add & Norm      │                 │  │  │  + Add & Norm      │                 │
│  └────────────────────┘                 │  │  │                    │                 │
│           │                              │  │  │  Feed Forward      │                 │
│    인코더 출력 ─────────────────────────┼──┤  │  Network           │                 │
│                                         │  │  │  + Add & Norm      │                 │
└─────────────────────────────────────────┘  │  └────────────────────┘                 │
                                              │           │                              │
                                              │    [Linear + Softmax]                    │
                                              │           │                              │
                                              │     다음 토큰 확률                       │
                                              └─────────────────────────────────────────┘

  인코더: 입력을 이해하는 역할 (양방향)
  디코더: 출력을 생성하는 역할 (왼→오 단방향)
  Cross-Attention: 디코더가 인코더 출력을 참조
```

### Add & Norm (잔차 연결 + 층 정규화)

```
잔차 연결 (Residual Connection):
  출력 = Layer(x) + x     ← 입력을 그대로 더해줌!

  왜? 깊은 네트워크에서 기울기가 잘 흐르도록!
  (ResNet에서 배운 것과 같은 원리)

층 정규화 (Layer Normalization):
  각 샘플의 특성 값들을 평균 0, 분산 1로 정규화
  → 학습 안정화
```

### 마스킹의 차이

```
BERT의 마스킹 (MLM):
  입력:  "나는 [MASK] 학교에 [MASK]"
  예측:  [MASK₁] = "오늘"  [MASK₂] = "간다"
  → 양쪽 문맥을 모두 활용! ("나는" + "학교에" 모두 참고)

GPT의 마스킹 (Causal):
  입력:  "나는"
  예측:  → "오늘"
  입력:  "나는 오늘"
  예측:  → "학교에"
  → 왼쪽(과거)만 참고! 미래는 볼 수 없음!

  어텐션 마스크 시각화:

  BERT (양방향):           GPT (단방향):

     나는 오늘 학교에 간다      나는 오늘 학교에 간다
  나는  ✓    ✓    ✓    ✓    나는  ✓    ✗    ✗    ✗
  오늘  ✓    ✓    ✓    ✓    오늘  ✓    ✓    ✗    ✗
  학교에 ✓    ✓    ✓    ✓    학교에 ✓    ✓    ✓    ✗
  간다  ✓    ✓    ✓    ✓    간다  ✓    ✓    ✓    ✓

  (✓ = 볼 수 있음, ✗ = 볼 수 없음)
```

```
[연습 1] Self-Attention 손계산
  3개 단어의 임베딩이 다음과 같을 때:

  x₁ = [1, 0], x₂ = [0, 1], x₃ = [1, 1]

  Wq = [[1, 0], [0, 1]]  (항등 행렬로 단순화)
  Wk = [[1, 0], [0, 1]]
  Wv = [[1, 0], [0, 1]]

  (a) Q, K, V를 계산하시오

## 3.1 스케일링 법칙 (Scaling Laws)

### 핵심 발견: "크게 만들면 더 잘한다"

```
Kaplan et al. (2020) & Hoffmann et al. (2022, Chinchilla)의 발견:

  모델 성능 ∝ f(N, D, C)

  N: 모델 파라미터 수
  D: 학습 데이터 토큰 수
  C: 컴퓨팅 예산 (FLOPs)

  핵심 관계 (멱법칙, Power Law):

  Loss ≈ (N₀/N)^αN + (D₀/D)^αD + L₀

  → 파라미터, 데이터, 컴퓨팅을 늘리면 손실이 예측 가능하게 감소!
```

### Chinchilla 법칙 vs 기존 법칙

```
기존 관행 (GPT-3 시대):
  "파라미터를 최대한 늘리자!"
  GPT-3: 175B 파라미터, 300B 토큰으로 학습

Chinchilla 법칙 (2022):
  "파라미터와 데이터를 균형 있게 늘려야 한다!"
  최적 비율: 토큰 수 ≈ 20 × 파라미터 수

  Chinchilla: 70B 파라미터, 1.4T 토큰으로 학습
  → GPT-3보다 파라미터는 적지만 성능은 더 좋음!

  ┌────────────────────────────────────────────┐
  │  컴퓨팅 예산이 같을 때:                      │
  │                                              │
  │  방법 A: 큰 모델 + 적은 데이터  ← 비효율적!  │
  │  방법 B: 적절 모델 + 많은 데이터 ← 최적!     │
  └────────────────────────────────────────────┘
```

### 최신 트렌드: Densing Law와 테스트 타임 컴퓨팅

```
Densing Law (2025):
  "같은 성능을 내는 데 필요한 파라미터 수가
   약 3.5개월마다 절반으로 줄어든다"

  → 모델 효율성이 기하급수적으로 향상!
  → 데이터 품질과 학습 기법의 발전 덕분

테스트 타임 컴퓨팅 (Test-Time Compute, 2024~):
  기존: 학습 시에만 컴퓨팅 투자
  최신: 추론(답변 생성) 시에도 컴퓨팅 투자!

  예: OpenAI o1/o3 모델
  → "더 오래 생각하면 더 좋은 답을 낸다"
  → Chain-of-Thought를 자동으로 수행
  → 어려운 문제에 더 많은 컴퓨팅 할당
```

## 3.2 Flash Attention

### 문제: 어텐션은 메모리를 너무 많이 먹는다

```
표준 Self-Attention의 메모리 문제:

  시퀀스 길이 N에 대해:
  - 어텐션 행렬 크기: N × N
  - N = 1,000  → 1M 원소 (괜찮음)
  - N = 10,000 → 100M 원소 (좀 큼)
  - N = 100,000 → 10B 원소 (메모리 폭발!)

  메모리 복잡도: O(N²)  ← 이것이 병목!
```

### Flash Attention의 핵심 아이디어

```
핵심: "수학은 그대로, 메모리 접근 방식만 바꾸자!"

표준 방식:
  1. QKᵀ 전체를 HBM(메인 메모리)에 저장  ← 느림
  2. Softmax 계산
  3. V와 곱셈

Flash Attention 방식:
  1. Q, K, V를 블록 단위로 SRAM(캐시)에 로드  ← 빠름!
  2. 블록별로 어텐션 계산
  3. 결과만 HBM에 저장
  4. 전체 N×N 행렬을 절대 HBM에 만들지 않음!

  ┌─────────────────────────────────────────────┐
  │  GPU 메모리 계층                              │
  │                                               │
  │  SRAM (on-chip):  ~20MB,  ~19TB/s 대역폭     │
  │      ↕ (Flash Attention은 여기서 계산!)       │
  │  HBM (off-chip):  ~40GB,  ~1.5TB/s 대역폭    │
  │      ↕                                        │
  │  Main RAM:        ~1TB,   ~12.8GB/s 대역폭   │
  │                                               │
  │  속도 차이: SRAM이 HBM보다 약 13배 빠름!      │
  └─────────────────────────────────────────────┘

결과:
  - 메모리 사용: O(N²) → O(N)  (N에 선형!)
  - 속도: 2~4배 빨라짐
  - 수학적으로 정확히 동일한 결과 (근사가 아님!)
```

### Flash Attention의 발전

```
Flash Attention 1 (2022): 기본 아이디어 - IO-aware attention
Flash Attention 2 (2023): 병렬성 개선, 2× 추가 속도 향상
Flash Attention 3 (2024): H100 GPU 최적화, FP8 지원
FlashInfer (2025): 다양한 KV-cache 형식 지원, JIT 컴파일
```

## 3.4 Mixture of Experts (MoE)

### 핵심 아이디어: "전문가 팀"

```
Dense 모델 (기존):
  모든 입력이 모든 파라미터를 통과
  → 파라미터 수 = 활성 파라미터 수

MoE 모델:
  입력마다 일부 "전문가"만 활성화
  → 전체 파라미터 >> 활성 파라미터

  ┌─────────────────────────────────────────────┐
  │  Router (라우터): "이 토큰은 어떤 전문가가    │
  │                    처리해야 할까?"              │
  │                                               │
  │  토큰 → Router → Expert 2, Expert 5 선택      │
  │                   (Top-2 라우팅)               │
  │                                               │
  │  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐        │
  │  │ E1   │ │ E2 ■ │ │ E3   │ │ E4   │        │
  │  │ (OFF)│ │ (ON) │ │ (OFF)│ │ (OFF)│        │
  │  └──────┘ └──────┘ └──────┘ └──────┘        │
  │  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐        │
  │  │ E5 ■ │ │ E6   │ │ E7   │ │ E8   │        │
  │  │ (ON) │ │ (OFF)│ │ (OFF)│ │ (OFF)│        │
  │  └──────┘ └──────┘ └──────┘ └──────┘        │
  │                                               │
  │  출력 = w₂×E2(x) + w₅×E5(x)                  │
  │  (라우터 확률로 가중 합산)                      │
  └─────────────────────────────────────────────┘
```

### 실제 사례

```
Mixtral 8×7B (2023, Mistral):
  - 8개 전문가, 각 7B 파라미터
  - 전체 파라미터: ~46.7B
  - 활성 파라미터: ~12.9B (토큰당 2개 전문가)
  - 성능: Llama 2 70B와 비슷하지만 추론 6× 빠름!

DeepSeek V3 (2024):
  - 256개 전문가 + 1개 공유 전문가
  - 전체 파라미터: 671B
  - 활성 파라미터: 37B
  - Fine-grained Expert Segmentation 사용

핵심 장점:
  모델 용량(capacity) = 전체 파라미터에 비례
  추론 비용(cost) = 활성 파라미터에 비례
  → 큰 모델을 저렴하게 운용 가능!
```

### MoE의 도전 과제

```
1. Load Balancing (부하 분산):
   특정 전문가에게만 토큰이 몰리는 문제
   → Auxiliary Loss로 균등 분배 유도

2. 통신 오버헤드:
   전문가가 여러 GPU에 분산되면 통신 비용 발생
   → Expert Parallelism으로 해결

3. 학습 불안정성:
   라우터 학습이 불안정할 수 있음
   → Router Z-Loss, Expert Choice 등 기법 사용
```

## 3.5 Rotary Position Embeddings (RoPE)

### 기존 위치 인코딩의 한계

```
사인/코사인 위치 인코딩 (원본 트랜스포머):
  - 절대 위치만 인코딩
  - 학습 시 본 길이를 넘으면 성능 저하
  - 상대 위치 정보가 간접적

학습 가능 위치 인코딩 (BERT, GPT-2):
  - 각 위치에 학습 가능한 벡터 할당
  - 최대 길이가 고정됨 (예: 512, 2048)
  - 외삽(extrapolation) 불가
```

### RoPE의 핵심 아이디어

```
핵심: "위치 정보를 벡터에 더하지 말고, 회전시키자!"

2D 평면에서의 직관:

  위치 0의 벡터: →      (0도)
  위치 1의 벡터:  ↗     (θ도 회전)
  위치 2의 벡터:   ↑    (2θ도 회전)
  위치 3의 벡터:  ↖     (3θ도 회전)

  두 벡터의 내적은 "회전 각도의 차이"에만 의존
  → 자연스럽게 상대 위치 인코딩이 됨!

수학적으로:
  f(q, pos_m) · f(k, pos_n) = g(q, k, m-n)

  → 위치 m의 Query와 위치 n의 Key의 내적은
     오직 상대 거리 (m-n)에만 의존!

d차원으로 확장:
  d차원 벡터를 d/2개의 2D 쌍으로 나눔
  각 쌍을 서로 다른 주파수(θᵢ)로 회전

  θᵢ = 10000^(-2i/d)  (사인/코사인 인코딩과 유사한 주파수)
```

### RoPE의 장점과 활용

```
장점:
  1. 파라미터 없음 (학습할 추가 파라미터 불필요)
  2. 상대 위치를 자연스럽게 인코딩
  3. 길이 외삽 가능 (학습보다 긴 시퀀스에 일반화)
  4. 선형 Self-Attention과도 호환

채택 현황:
  - LLaMA / LLaMA 2 / LLaMA 3
  - Mistral / Mixtral
  - Qwen / Qwen 2
  - PaLM / Gemma
  → 사실상 현대 LLM의 표준!

확장:
  - YaRN (2023): 긴 문맥으로 확장 시 주파수 조정
  - NTK-aware Scaling: 외삽 성능 개선
  - Dynamic NTK: 추론 시 동적으로 조정
```

## 3.6 KV-Cache 최적화

### KV-Cache란?

```
GPT 스타일 모델의 생성 과정:

  토큰 1개 생성할 때마다 전체 시퀀스에 대해 어텐션 계산?
  → 이전 토큰의 K, V는 변하지 않음!
  → 캐시해두면 중복 계산을 피할 수 있다!

Without KV-Cache:
  Step 1: [A]         → Q₁, K₁, V₁ 계산 → B 생성
  Step 2: [A, B]      → Q₁₂, K₁₂, V₁₂ 전체 재계산 → C 생성
  Step 3: [A, B, C]   → Q₁₂₃, K₁₂₃, V₁₂₃ 전체 재계산 → D 생성
  → 매번 이전 계산을 반복! 비효율적!

With KV-Cache:
  Step 1: [A]         → K₁, V₁ 저장, Q₁만으로 계산 → B 생성
  Step 2: [B]         → K₂, V₂ 추가 저장, Q₂ + Cache(K₁V₁) → C 생성
  Step 3: [C]         → K₃, V₃ 추가 저장, Q₃ + Cache(K₁₂V₁₂) → D 생성
  → 새 토큰의 Q만 계산하면 됨!
```

### KV-Cache의 메모리 문제와 해결책

```
문제: KV-Cache는 시퀀스 길이에 비례하여 메모리 증가

  메모리 = 2 × layers × heads × seq_len × head_dim × batch_size

  LLaMA 2 70B, 시퀀스 4096:
  → KV-Cache ≈ 2 × 80 × 64 × 4096 × 128 × 2bytes ≈ 10.7GB per batch!

  시퀀스가 128K라면? → ~330GB!  (현실적으로 불가능)

해결 기법들:

  ┌─────────────────────────────────────────────────┐
  │  1. Multi-Query Attention (MQA)                  │
  │     모든 Head가 하나의 K, V를 공유                │
  │     메모리: 1/h로 감소 (h = Head 수)              │
  │     예: PaLM, StarCoder                          │
  │                                                   │
  │  2. Grouped-Query Attention (GQA)                 │
  │     Head를 그룹으로 묶어 K, V 공유                 │
  │     MQA와 MHA의 중간                              │
  │     예: LLaMA 2 70B, Mistral 7B                  │
  │                                                   │
  │  3. KV-Cache Eviction (퇴거)                     │
  │     오래된/덜 중요한 KV를 삭제                     │
  │     H2O: "Heavy Hitter Oracle" - 중요 토큰 유지   │
  │     StreamingLLM: Attention Sink + 최근 윈도우    │
  │                                                   │
  │  4. KV-Cache Quantization                        │
  │     KV를 FP16 → INT8/INT4로 양자화               │
  │     메모리 2~4× 절약, 성능 손실 미미               │
  │                                                   │
  │  5. KV-Cache Compression (2025 최신)              │
  │     PureKV: 초기 층에서 중요도 평가 후 압축        │
  │     ClusterAttn: 어텐션 클러스터 기반 압축         │
  │     Expected Attention: 미래 쿼리 분포 기반 압축   │
  └─────────────────────────────────────────────────┘
```

## 3.7 State Space Models (Mamba)

### 왜 트랜스포머의 대안이 필요한가?

```
트랜스포머의 근본적 한계:

  Self-Attention 복잡도: O(N²)

  N = 1K   →  1M 연산     ✅ 빠름
  N = 10K  →  100M 연산   ⚠️ 느려짐
  N = 100K →  10B 연산    ❌ 매우 느림
  N = 1M   →  1T 연산     💀 사실상 불가능

  → 매우 긴 시퀀스 (책 한 권, 전체 코드베이스 등)에는 비효율적!
```

### State Space Model의 핵심

```
SSM의 아이디어: 제어 이론의 상태 공간 모델을 시퀀스 모델링에 적용

연속 시간 SSM:
  h'(t) = Ah(t) + Bx(t)     (상태 업데이트)
  y(t)  = Ch(t) + Dx(t)     (출력 계산)

이산화 (Discretization):
  hₜ = Āhₜ₋₁ + B̄xₜ        (이전 상태 + 현재 입력)
  yₜ = Chₜ                  (출력)

핵심 특성:
  - 학습: 합성곱(Convolution)으로 병렬 처리 가능 → O(N log N)
  - 추론: 순환(Recurrence)으로 한 스텝씩 → O(1) per step

  ┌─────────────────────────────────────────┐
  │  학습 모드 (병렬):                       │
  │  전체 시퀀스를 FFT 기반 합성곱으로 처리   │
  │  → GPU 병렬 처리에 최적!                 │
  │                                          │
  │  추론 모드 (순환):                       │
  │  RNN처럼 한 토큰씩 처리                  │
  │  → KV-Cache 불필요! 상수 메모리!         │
  └─────────────────────────────────────────┘
```

### Mamba: 선택적 State Space Model

```
기존 SSM의 문제:
  A, B, C 행렬이 입력과 무관하게 고정
  → 입력에 따라 다르게 반응할 수 없음 (content-aware 불가)
  → 어텐션의 장점을 못 살림

Mamba의 해결:
  B, C, Δ를 입력에 의존하게 만듦! (Selective SSM)

  B = f_B(x)    ← 입력에 따라 달라짐!
  C = f_C(x)    ← 입력에 따라 달라짐!
  Δ = f_Δ(x)    ← 이산화 스텝 크기도 입력에 따라!

  → 중요한 정보: Δ를 크게 → 상태에 많이 반영
  → 불필요한 정보: Δ를 작게 → 무시

  이것이 "선택적(Selective)" 메커니즘!
```

### Mamba vs Transformer 비교

```
┌─────────────────┬──────────────────┬──────────────────┐
│                 │   Transformer    │     Mamba        │
├─────────────────┼──────────────────┼──────────────────┤
│ 시퀀스 복잡도    │ O(N²)           │ O(N)             │
│ 추론 메모리      │ O(N) KV-Cache   │ O(1) 상수        │
│ 추론 처리량      │ 기준             │ 5× 높음          │
│ 학습 병렬화      │ 완전 병렬        │ 병렬 (합성곱)    │
│ 장기 의존성      │ 명시적 (직접)    │ 압축된 상태      │
│ In-context Learn│ 강함             │ 약함 (개선 중)   │
│ 언어 모델링      │ 강함             │ 비슷~경쟁        │
│ 하드웨어 효율    │ GPU 최적화 성숙  │ 개선 중          │
└─────────────────┴──────────────────┴──────────────────┘

하이브리드 접근 (2024~):
  Jamba (AI21):  Mamba + Transformer 블록 교대 배치
  Zamba (Zyphra): Mamba + 공유 Attention 층

  → 두 아키텍처의 장점을 결합!
  → 장거리 효율성(Mamba) + 정밀한 참조(Attention)
```

## 3.8 Ring Attention

### 핵심: 여러 GPU로 긴 시퀀스를 나눠 처리하기

```
문제: 단일 GPU에 시퀀스 전체를 올릴 수 없을 만큼 길다면?

Ring Attention 아이디어:
  1. 시퀀스를 N개 블록으로 나눠 N개 GPU에 분배
  2. GPU들을 "링(ring)" 형태로 연결
  3. 각 GPU는 자신의 Q 블록을 가지고 있음
  4. K, V 블록이 링을 따라 순환하며 전달됨
  5. 통신과 계산을 겹침(overlap)!

  ┌──────────────────────────────────────────────┐
  │          Ring Attention 동작 원리              │
  │                                                │
  │       GPU 0          GPU 1                     │
  │    ┌────────┐     ┌────────┐                  │
  │    │ Q₀     │     │ Q₁     │                  │
  │    │ K₀→    │────→│ K₀→    │──→              │
  │    │ V₀→    │────→│ V₀→    │──→              │
  │    └────────┘     └────────┘                  │
  │         ↑                          ↓           │
  │       GPU 3          GPU 2                     │
  │    ┌────────┐     ┌────────┐                  │
  │    │ Q₃     │     │ Q₂     │                  │
  │    │ ←K₃    │←────│ ←K₃    │                  │
  │    │ ←V₃    │←────│ ←V₃    │                  │
  │    └────────┘     └────────┘                  │
  │                                                │
  │  → K,V가 링을 한 바퀴 돌면 모든 쌍 계산 완료!  │
  │  → 통신을 계산으로 숨김 (overlap)               │
  │  → 시퀀스 길이 ∝ GPU 수  (거의 무한 확장!)     │
  └──────────────────────────────────────────────┘

성과:
  - 100M+ 토큰 시퀀스 학습 가능
  - 기존 메모리 효율 방법 대비 500× 이상 긴 시퀀스
  - Striped Attention: Ring Attention 대비 1.45~1.65× 속도 향상
```

  (c) Flash Attention이 이 IO를 어떻게 줄이는지 설명하시오.

[연습 6] RoPE 구현
  PyTorch로 RoPE를 구현해보시오:

  import torch

  def apply_rope(x, seq_len, dim):
      """
      x: (batch, seq_len, dim) 텐서
      RoPE를 적용한 결과를 반환
      """
      position = torch.arange(seq_len).unsqueeze(1)  # (seq_len, 1)
      div_term = 10000 ** (torch.arange(0, dim, 2).float() / dim)

      # 각 위치의 회전 각도
      theta = position / div_term  # (seq_len, dim//2)

      # x를 2D 쌍으로 분리
      x1 = x[..., 0::2]  # 짝수 인덱스
      x2 = x[..., 1::2]  # 홀수 인덱스

      # 회전 적용
      cos_theta = torch.cos(theta)
      sin_theta = torch.sin(theta)

      out1 = x1 * cos_theta - x2 * sin_theta
      out2 = x1 * sin_theta + x2 * cos_theta

      # 결합
      out = torch.stack([out1, out2], dim=-1).flatten(-2)
      return out
```
