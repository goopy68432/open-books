# 📐 행렬과 선형 공간: 데이터를 다루는 법

## 간단한 소개

지난 시간에 행렬이 "숫자를 표로 정리한 것"이라고 배웠죠?
이번에는 행렬로 할 수 있는 **신기한 일들**을 알아볼 거예요.

행렬은 단순한 표가 아니라, 데이터를 **변환하고 조합하는 강력한 도구**예요!

---

## 1. 행렬 표기법 — 행렬을 읽는 방법

### 쉽게 말하면?

행렬은 보통 대문자 알파벳으로 쓰고, 크기를 "행 × 열"로 표현해요.

```
        열1  열2  열3
행1  [  1    2    3  ]
행2  [  4    5    6  ]

→ 이것은 2×3 행렬 (2행 3열)
→ 보통 A라고 이름 붙여요
```

### 일상 비유

영화관 좌석을 생각해 보세요!

- "3행 5열" → 3번째 줄, 5번째 자리
- 행렬도 같아요: "2행 3열의 값" = 그 위치에 있는 숫자

---

## 2. 전치 (Transpose) — 행과 열을 뒤집기

### 쉽게 말하면?

행렬을 **대각선으로 뒤집는 것**이에요. 가로를 세로로, 세로를 가로로!

```
원래 행렬 A          전치 행렬 Aᵀ
[ 1  2  3 ]          [ 1  4 ]
[ 4  5  6 ]    →     [ 2  5 ]
                     [ 3  6 ]

2×3 행렬     →     3×2 행렬
```

### 일상 비유

성적표를 생각해 보세요.

**원래 (학생별로 정리)**:
```
       국어  영어
철수 [  85    90 ]
영희 [  92    88 ]
```

**전치 (과목별로 정리)**:
```
       철수  영희
국어 [  85    92 ]
영어 [  90    88 ]
```

같은 데이터인데 보는 관점만 바꾼 거예요!

### 왜 중요해?

AI에서 데이터의 방향을 맞춰야 할 때 전치를 자주 써요.
마치 가로로 찍은 사진을 세로로 돌리는 것처럼요.

---

## 3. 행렬 곱셈 — 두 변환을 연결하는 것

### 쉽게 말하면?

행렬 곱셈은 **두 개의 변환을 하나로 합치는 것**이에요.

### 일상 비유

번역을 생각해 보세요:

```
기계 A: 한국어 → 영어
기계 B: 영어 → 일본어

A × B = 한국어 → 일본어 (두 번역을 합침!)
```

### 행렬 곱셈 방법

```
A = [ 1  2 ]     B = [ 5  6 ]
    [ 3  4 ]         [ 7  8 ]

A × B = ?
```

**계산 방법**: A의 가로줄과 B의 세로줄을 짝지어 곱하고 더해요.

```
1번째 결과 = (1×5) + (2×7) = 5 + 14 = 19
2번째 결과 = (1×6) + (2×8) = 6 + 16 = 22
3번째 결과 = (3×5) + (4×7) = 15 + 28 = 43
4번째 결과 = (3×6) + (4×8) = 18 + 32 = 50

A × B = [ 19  22 ]
        [ 43  50 ]
```

### 중요한 규칙! ⚠️

일반 곱셈과 다르게, **행렬 곱셈은 순서가 중요해요!**

```
A × B ≠ B × A  (대부분의 경우!)
```

생각해보면 당연해요:
- "한국어→영어" 다음에 "영어→일본어" = 한국어→일본어
- "영어→일본어" 다음에 "한국어→영어" = ??? (말이 안 됨!)

### 왜 중요해?

AI의 신경망은 행렬 곱셈의 연속이에요!
데이터가 각 층을 지날 때마다 행렬 곱셈이 일어나요.

## 4. 선형 결합 — 벡터를 섞어서 새 벡터 만들기

### 쉽게 말하면?

여러 재료를 섞어서 새로운 것을 만드는 거예요.

### 일상 비유: 물감 섞기 🎨

```
빨간 물감 2방울 + 파란 물감 3방울 = 보라색 물감

수학으로: 2 × [빨강] + 3 × [파랑] = [보라]
```

벡터로 표현하면:

```
벡터 a = [1, 0]  (오른쪽 방향)
벡터 b = [0, 1]  (위쪽 방향)

2×a + 3×b = 2×[1,0] + 3×[0,1] = [2, 3]
→ 오른쪽으로 2, 위로 3 이동!
```

### 왜 중요해?

AI가 데이터를 처리할 때, 여러 특징(벡터)을 적절히 섞어서
새로운 의미를 만들어내요. 이게 바로 **선형 결합**이에요!

---

## 5. 선형 독립 — 진짜 새로운 방향인가?

### 쉽게 말하면?

친구들과 길을 찾을 때:
- 한 명이 "동쪽으로 가자" → 새로운 정보! ✅
- 다른 친구가 "서쪽으로 가자" → 그건 동쪽의 반대니까 새로운 정보가 아님 ❌
- 또 다른 친구가 "북쪽으로 가자" → 새로운 정보! ✅

**선형 독립**: 한 벡터가 다른 벡터들로 만들 수 없을 때

### 일상 비유

요리 재료를 생각해 보세요:

| 재료 조합 | 선형 독립? |
|-----------|-----------|
| 소금, 설탕, 식초 | ✅ 각각 다른 맛 |
| 소금, 소금 2배 | ❌ 같은 재료를 양만 바꾼 것 |
| 동쪽, 북쪽 | ✅ 완전히 다른 방향 |
| 동쪽, 서쪽 | ❌ 동쪽의 반대 = 동쪽 × (-1) |

### 왜 중요해?

AI가 데이터를 분석할 때, **진짜 새로운 정보**만 골라내야 효율적이에요.
중복된 정보는 빼는 거죠!

## 6. 생성(Span) — 만들 수 있는 모든 것

### 쉽게 말하면?

주어진 벡터들을 섞어서(선형 결합해서) **만들 수 있는 모든 벡터의 모음**이에요.

### 일상 비유

```
빨강 물감 + 파랑 물감으로 만들 수 있는 색:
→ 빨강, 파랑, 보라, 분홍, 남색... (다양한 비율로!)
→ 이 모든 색의 모음 = Span

하지만 노랑은?
→ 빨강+파랑으로는 절대 못 만듦! Span에 포함 안 됨!
```

---

## 7. 기저(Basis)와 차원(Dimension)

### 기저: 공간을 표현하는 최소한의 방향

**기저**는 어떤 공간의 모든 점을 표현할 수 있는 **최소한의 벡터 세트**예요.

### 일상 비유

지도에서 위치를 알려줄 때:

```
2차원 지도: "동쪽으로 3km, 북쪽으로 2km"
→ 기저 = {동쪽, 북쪽} → 2개면 충분!
→ 차원 = 2

3차원 공간: "동쪽 3km, 북쪽 2km, 위로 100m"
→ 기저 = {동쪽, 북쪽, 위쪽} → 3개 필요!
→ 차원 = 3
```

### 차원: 기저 벡터의 개수

| 공간 | 기저 개수 | 차원 |
|------|----------|------|
| 직선 위 | 1개 | 1차원 |
| 평면 위 | 2개 | 2차원 |
| 입체 공간 | 3개 | 3차원 |
| AI 데이터 공간 | 수백~수천 개 | 수백~수천 차원! |

### 왜 중요해?

AI가 다루는 데이터는 수천 차원인 경우가 많아요.
사람은 3차원까지만 상상할 수 있지만, AI는 아무 문제 없이 처리해요! 😎

## 8. 치역(Range)과 영공간(Null Space)

### 치역: 변환 후 갈 수 있는 곳

행렬(변환)을 통과한 후 **도달할 수 있는 모든 결과**예요.

### 영공간: 변환하면 사라지는 것들

변환을 했더니 **0이 되어버리는 것들의 모임**이에요.

### 일상 비유: 그림자 🌞

3D 물체에 빛을 비추면 2D 그림자가 생기죠?

```
3D 물체  →  [빛 비추기 변환]  →  2D 그림자

치역 = 가능한 모든 그림자 모양
영공간 = 그림자에서 사라진 높이 정보
```

예를 들어:
- 위에서 빛을 비추면 → 높이 정보가 사라짐 (영공간)
- 그림자에 나타난 가로×세로 정보 → 치역

### 왜 중요해?

AI가 데이터를 변환할 때 어떤 정보가 보존되고(치역),
어떤 정보가 사라지는지(영공간) 아는 것이 중요해요.

## 9. 랭크-널리티 정리 — 보존과 손실의 균형

### 쉽게 말하면?

```
원래 차원 = 치역의 차원 + 영공간의 차원
(전체 정보) = (살아남은 정보) + (사라진 정보)
```

### 일상 비유

100만 원을 가지고 있었다면:

```
100만 원 = 쓴 돈 + 남은 돈
```

정보도 마찬가지! 변환 과정에서 사라진 정보 + 남은 정보 = 원래 정보

### 왜 중요해?

이걸 알면 "이 변환을 하면 정보가 얼마나 손실될까?"를 계산할 수 있어요.
AI 모델을 설계할 때 정보 손실을 최소화하는 게 중요하거든요!
