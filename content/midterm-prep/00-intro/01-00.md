# CH01. 딥러닝 개요 및 역사

## 1-1. Hierarchical Representation (계층적 표현)

### 🎯 한 줄 결론
데이터의 의미를 단순한 것부터 복잡한 것까지 **단계별로 쌓아올려** 이해하는 방식이다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

백엔드에서 로그를 분석할 때를 떠올려 보자:
- 1단계: 원본 텍스트 로그 → 파싱
- 2단계: 파싱된 필드 → 패턴 그룹핑
- 3단계: 패턴 → "장애 유형" 분류

딥러닝도 이와 같다. 이미지를 예로 들면:
- 1단계(하위 층): 점, 선, 엣지 같은 단순한 패턴 감지
- 2단계(중간 층): 눈, 코, 입 같은 부분 인식
- 3단계(상위 층): "이것은 고양이다" 같은 의미 판단

이걸 **계층적 표현**이라 한다. 각 층이 이전 층의 출력을 입력으로 받아 더 추상적인 특징을 만드는 것이다.

→ "남에게 설명한다면: 단순한 패턴을 조합해서 복잡한 의미를 단계별로 쌓아 올리는 것이 딥러닝의 핵심이다."

**[중급 — 어떻게 작동하는가]**

소프트웨어로 비유하면 **미들웨어 파이프라인**이다:

```
Request → [Auth 미들웨어] → [Parsing 미들웨어] → [Validation 미들웨어] → [Business Logic]
```

각 미들웨어가 입력을 가공해서 다음으로 넘기듯, 신경망의 각 층(layer)이 데이터를 가공한다.

- 각 층은 **가중치(weight)**라는 설정값을 가진다 → 설정 파일의 파라미터와 비슷
- 학습 = 이 설정값을 데이터에 맞게 자동으로 조정하는 과정
- "딥(Deep)"러닝 = 이 파이프라인이 **깊다**(층이 많다)는 뜻

핵심 차이: 전통 ML은 사람이 "어떤 특징을 볼지" 직접 정해줬지만(feature engineering), 딥러닝은 이 과정 자체를 데이터에서 자동으로 학습한다.

→ "남에게 설명한다면: 미들웨어 파이프라인처럼 각 층이 데이터를 단계별로 가공하는데, 어떻게 가공할지를 데이터가 알아서 결정하게 하는 것이다."

### ⚡ 핵심 요약
- **왜 중요한가**: 사람이 직접 특징을 설계하지 않아도 되므로, 이미지·음성·텍스트 같은 복잡한 데이터를 다룰 수 있게 됨
- **어디에 쓰이는가**: CNN(이미지), Transformer(텍스트) 등 거의 모든 딥러닝 모델의 기본 원리
- **핵심**: 층이 깊을수록 더 추상적이고 복잡한 패턴을 표현할 수 있다

### 🔑 결국 뭐가 중요한가
1. 딥러닝의 "딥" = 층이 많다 = 계층적 표현이 깊다
2. 각 층은 이전 층의 출력을 받아 더 높은 수준의 특징을 만든다
3. 이 과정이 자동이라는 점이 전통 ML과의 핵심 차이

## 1-2. Generalization (일반화)

### 🎯 한 줄 결론
훈련할 때 **안 본 데이터**에서도 잘 작동하는 능력이다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

API 서버의 부하 테스트를 생각해 보자:
- 테스트 환경에서 잘 돌아간다 → 훈련 데이터에서 잘 작동하는 것
- **실제 프로덕션**에서도 잘 돌아간다 → **일반화**가 잘 된 것
- 테스트에서는 완벽한데 프로덕션에서 죽는다 → 일반화 실패 (= 과적합)

딥러닝 모델도 마찬가지다:
- 훈련 데이터만 잘 맞추면 의미 없다 (시험 답을 외운 것)
- 진짜 실력은 **처음 보는 데이터**에서의 성능으로 판단한다

→ "남에게 설명한다면: 테스트 환경이 아니라 실제 프로덕션에서 잘 돌아가는지가 진짜 실력이듯, 모델도 안 본 데이터에서 잘 작동해야 진짜 학습한 것이다."

**[중급 — 어떻게 작동하는가]**

일반화를 수치로 측정하는 방법:

```
Generalization Gap = 테스트 에러 - 훈련 에러
```

이 수식이 말하는 것은: "프로덕션 에러율에서 테스트 환경 에러율을 빼면, 모델이 얼마나 훈련 데이터에만 맞춰져 있는지 알 수 있다."

- Gap이 작다 → 훈련과 실전 성능이 비슷 → 일반화 좋음
- Gap이 크다 → 훈련에서만 잘하고 실전에서 망함 → 과적합

일반화를 좋게 만드는 핵심 기법들:
| 기법 | 비유 |
|------|------|
| 정규화(Regularization) | 코드에 린트 룰을 걸어서 과도한 복잡성 방지 |
| Dropout | 팀원 일부를 랜덤으로 빼고도 서비스가 돌아가게 설계 |
| Data Augmentation | 같은 테스트 케이스를 변형해서 더 많은 엣지 케이스 생성 |
| Early Stopping | 성능 지표 모니터링하다가 악화되면 배포 중단 |

→ "남에게 설명한다면: 일반화는 모델의 프로덕션 레디니스(production-readiness)다. 훈련 데이터에만 최적화되지 않고 범용적으로 잘 작동하는지가 핵심이다."

### ⚡ 핵심 요약
- **왜 중요한가**: 아무리 훈련 정확도가 높아도 실전에서 못 쓰면 의미 없음
- **어디에 쓰이는가**: 모든 ML/DL 모델의 최종 평가 기준
- **무엇과 비교**: 과적합(overfitting)은 일반화의 실패 상태
- **주의**: 훈련 정확도 99%는 자랑이 아니다. 테스트 정확도가 핵심.

### 🔑 결국 뭐가 중요한가
1. 모델 평가의 유일한 진짜 기준 = 안 본 데이터에서의 성능
2. Generalization Gap이 작을수록 좋은 모델
3. 과적합 방지 기법(정규화, dropout 등)은 전부 일반화를 위한 것

## 1-3. MLE vs MAP

### 🎯 한 줄 결론
MLE는 **증거(데이터)만** 보고 판단하고, MAP는 **증거 + 사전 경험**을 합쳐서 판단한다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

장애 원인을 분석하는 두 가지 접근을 비유해 보자:

**MLE 방식** (Maximum Likelihood Estimation = 최대 우도 추정):
- "로그만 보겠다. 로그가 가리키는 가장 그럴듯한 원인을 고르자."
- 순수하게 **현재 데이터(증거)**만으로 판단

**MAP 방식** (Maximum A Posteriori = 최대 사후 확률 추정):
- "로그도 보고, 과거 장애 이력(경험)도 같이 고려하겠다."
- **데이터 + 사전 지식(prior)**을 함께 활용

만약 로그에 DB 타임아웃이 3번 찍혔다면:
- MLE: "DB가 원인이다" (데이터만 봄)
- MAP: "하지만 이 DB는 5년간 한 번도 문제없었고, 최근 네트워크 공사가 있었으니 네트워크가 더 의심된다" (경험까지 반영)

→ "남에게 설명한다면: MLE는 현재 증거만 보는 판단, MAP는 과거 경험까지 합쳐서 보는 판단이다."

**[중급 — 어떻게 작동하는가]**

둘의 관계를 코드로 표현하면:

```python
# MLE: 데이터에서 가장 그럴듯한 파라미터 찾기
best_params = argmax(likelihood(data, params))

# MAP: 데이터 + 사전 지식을 합쳐서 파라미터 찾기
best_params = argmax(likelihood(data, params) * prior(params))
```

여기서:
- **likelihood** (우도): "이 설정(params)이 맞다면, 이 데이터가 나올 확률은 얼마인가?"
- **prior** (사전 확률): "이 설정이 일반적으로 합리적인가?"에 대한 사전 믿음

딥러닝에서 이것이 왜 중요한가:
| 프레임워크 | 딥러닝에서의 대응 |
|-----------|------------------|
| MLE | 순수하게 손실 함수만 최소화: `loss(data, model)` |
| MAP | 손실 + 정규화: `loss(data, model) + λ * regularization(model)` |

즉, **L2 정규화(weight decay)는 사실 MAP를 하고 있는 것**이다. "가중치는 0에 가까운 게 좋다"는 사전 지식(가우시안 prior)을 넣은 것.

핵심 관계: `MAP = MLE + 사전 지식`. 사전 지식이 "아무거나 다 OK"(균등 분포)이면 MAP = MLE가 된다.

→ "남에게 설명한다면: 딥러닝에서 정규화를 넣는 것은 곧 MAP를 하는 것이다. 데이터만 믿지 말고, 모델이 너무 복잡해지지 않게 사전 제약을 거는 것이다."

### ⚡ 핵심 요약
- **왜 중요한가**: 딥러닝의 정규화가 왜 작동하는지의 이론적 근거
- **어디에 쓰이는가**: 모든 손실 함수 설계, 정규화 기법의 수학적 해석
- **핵심**: L2 정규화 = 가우시안 사전 확률. L1 정규화 = 라플라스 사전 확률
- **주의**: MLE는 데이터가 적으면 과적합 위험이 크다 (동전 3번 던져서 3번 앞면 → "앞면 확률 100%"라고 결론)

### 🔑 결국 뭐가 중요한가
1. MLE = 데이터만, MAP = 데이터 + 사전 지식
2. 딥러닝의 `loss + regularization` 구조가 곧 MAP
3. 데이터가 많으면 MLE와 MAP 결과가 수렴한다 (사전 지식의 영향이 줄어듦)

## 1-4. Overparameterized (과매개변수화)

### 🎯 한 줄 결론
모델의 조절 가능한 설정값(파라미터)이 훈련 데이터 수보다 **훨씬 많은** 상태다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

설정 파일에 10개의 옵션이 있는데, 테스트 케이스는 3개뿐이라고 생각해 보자. 3개의 테스트만 통과하면 되므로, 설정값을 맞추는 방법이 무수히 많다. 이게 과매개변수화다.

전통적 통계에서는 이게 나쁜 것이었다 (방정식보다 미지수가 많으면 답이 무한개). 그런데 현대 딥러닝에서는 오히려 **이 상태에서도 잘 작동**한다는 게 미스터리이자 핵심 연구 주제다.

GPT 같은 모델은 파라미터가 수십억~수조 개인데, 이것이 왜 일반화가 되는지는 아직 완전히 풀리지 않았다.

→ "남에게 설명한다면: 딥러닝 모델은 설정값이 데이터보다 훨씬 많은데, 신기하게도 잘 작동한다. 왜 그런지는 아직 연구 중이다."

### ⚡ 핵심 요약
- **핵심**: 전통 이론으로는 과적합이 심해야 하지만, 실제로는 일반화가 잘 됨
- **연구 포인트**: Double Descent, Implicit Regularization 등이 이 현상을 설명하려는 시도

### 🔑 결국 뭐가 중요한가
1. 현대 딥러닝은 의도적으로 과매개변수화한다
2. SGD(학습 알고리즘)가 자동으로 "좋은 해"를 선택하는 경향이 있음
3. 이 현상의 이론적 설명은 딥러닝 연구의 최전선

## 1-5. Double Descent (이중 하강)

### 🎯 한 줄 결론
모델을 점점 복잡하게 만들면 에러가 올랐다가, **어떤 지점을 넘으면 다시 내려가는** 현상이다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

전통적 상식: 모델 복잡도를 키우면 처음엔 성능이 좋아지다가, 어느 순간 과적합으로 나빠진다 (U자 곡선).

그런데 실제로 관찰된 현상:
```
테스트 에러
  │
  │ ╲           ╱╲
  │   ╲       ╱    ╲
  │     ╲   ╱        ╲_________ ← 여기서 다시 좋아짐!
  │       ╲╱
  │        ↑
  │   여기가 최악 (Interpolation Threshold)
  └────────────────────────── 모델 복잡도
```

서버 확장 비유로 설명하면:
- 서버 1~3대: 트래픽 감당 어려움 (모델 너무 단순)
- 서버 5대: 딱 감당 가능 → 하지만 여유가 없어서 불안정 (Interpolation Threshold)
- 서버 20대: 여유롭게 처리, 트래픽 분산 → 오히려 안정적 (과매개변수화 영역)

→ "남에게 설명한다면: 모델을 겨우 충분한 크기로 만들면 오히려 불안정하고, 넉넉하게 크게 만들면 안정적으로 작동한다."

### ⚡ 핵심 요약
- **왜 중요한가**: "모델을 크게 만들면 과적합된다"는 전통 상식을 뒤집는 현상
- **핵심**: Interpolation Threshold (데이터를 겨우 외울 수 있는 크기)가 가장 위험한 지점
- **주의**: 이 현상은 epoch 수, 데이터 수에 대해서도 관찰됨 (epoch-wise, sample-wise double descent)

### 🔑 결국 뭐가 중요한가
1. 모델 크기의 "스윗 스팟"은 전통적 U자의 바닥이 아니라, 그 너머에 있을 수 있다
2. 현대 딥러닝이 "크게 만들수록 좋다"는 경향의 이론적 배경
3. 핵심은 interpolation threshold를 피하는 것 — 중간 크기가 가장 위험

## 2-1. Vector (벡터) / Norm (노름) / Inner Product (내적)

### 🎯 한 줄 결론
벡터는 **숫자의 리스트**이고, 노름은 그 리스트의 **크기(길이)**를 재는 것이고, 내적은 두 리스트가 **얼마나 같은 방향인지** 측정하는 것이다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

백엔드에서 매일 다루는 것으로 비유하면:

**벡터 = JSON 배열 또는 다차원 값**
```json
// 사용자 프로필 벡터
{"age": 25, "activity_score": 0.8, "purchase_count": 12}
// → 벡터: [25, 0.8, 12]
```

**노름 = 벡터의 크기를 재는 여러 가지 방법**
- L1 노름 (Manhattan): 각 값의 절대값을 다 더함 → 택시가 블록을 따라 가는 거리
- L2 노름 (Euclidean): 제곱 합의 제곱근 → 직선 거리
- 딥러닝에서 L1/L2는 정규화(regularization)에 사용: "가중치 벡터의 크기를 작게 유지해라"

**내적 = 두 벡터의 유사도 측정**
```python
# 두 사용자의 취향 벡터
user_a = [0.9, 0.1, 0.8]  # 액션 좋아, 로맨스 싫어, SF 좋아
user_b = [0.8, 0.2, 0.7]  # 비슷한 취향
dot_product = 0.9*0.8 + 0.1*0.2 + 0.8*0.7 = 1.30  # 높음 → 유사
```

→ "남에게 설명한다면: 벡터는 특성을 숫자 리스트로 표현한 것이고, 내적으로 두 리스트가 얼마나 비슷한지 측정한다."

**[중급 — 어떻게 작동하는가]**

**코사인 유사도**: 내적을 정규화한 것. 벡터의 크기(규모) 차이를 무시하고 **방향만** 비교한다.

```python
cosine_sim = dot(a, b) / (norm(a) * norm(b))  # -1 ~ 1 사이 값
```

이 수식이 말하는 것은: "두 벡터를 단위 벡터(길이 1)로 만든 뒤 내적을 구하면, 순수하게 방향 차이만 비교할 수 있다."

딥러닝에서의 사용:
- 단어 임베딩: "왕"과 "여왕"의 코사인 유사도가 높다
- 추천 시스템: 사용자 벡터와 아이템 벡터의 유사도로 추천

→ "남에게 설명한다면: 코사인 유사도는 두 벡터의 방향만 비교하는 정규화된 내적이다. 크기 차이에 영향받지 않는다."

### ⚡ 핵심 요약
- **핵심**: 딥러닝의 모든 데이터(이미지, 텍스트, 음성)는 결국 벡터로 변환되어 처리됨
- **주의**: L1 노름은 희소한(sparse) 결과를 유도하고, L2 노름은 고르게 작은 값을 유도한다

### 🔑 결국 뭐가 중요한가
1. 모든 데이터 = 벡터. 이미지도, 단어도, 소리도
2. 내적/코사인 유사도 = 딥러닝의 핵심 연산 (attention 메커니즘의 기초)
3. 노름 = 정규화의 기초 (L1 → 희소, L2 → 작게)

## 2-2. Matrix (행렬) / Linear Transformation (선형변환)

### 🎯 한 줄 결론
행렬은 벡터를 **다른 공간으로 변환하는 기계**이고, 신경망의 각 층이 하는 일이 바로 이것이다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

API Gateway를 생각해 보자:
- 요청(Request)이 들어오면 → 변환 규칙에 따라 → 다른 형태의 요청으로 바꿔서 내보낸다
- 이 "변환 규칙"이 **행렬**이고, 입출력 데이터가 **벡터**다

```
입력 벡터 [3차원]  →  행렬 곱(변환)  →  출력 벡터 [5차원]
```

신경망의 Fully Connected Layer가 정확히 이 구조다:
```python
output = weight_matrix @ input_vector + bias  # y = Wx + b
```

**선형변환**이란:
- 직선을 곡선으로 바꾸지 않는 변환
- 원점을 움직이지 않는 변환
- 비유: 엑셀 시트의 열을 곱하고 더하는 연산 (곱·합 연산만 사용)

활성화 함수가 없으면 아무리 많은 층을 쌓아도 결국 하나의 행렬 곱과 같다:
```python
# 활성화 없이 3개 층
W3 @ (W2 @ (W1 @ x)) = (W3 @ W2 @ W1) @ x = W_combined @ x
```
그래서 **비선형 활성화 함수가 필수**인 것이다.

→ "남에게 설명한다면: 행렬은 데이터를 한 형태에서 다른 형태로 바꾸는 변환기다. 신경망의 각 층이 하는 일이 바로 행렬 곱이다."

### ⚡ 핵심 요약
- **핵심**: 신경망 = 행렬 곱(선형변환) + 활성화 함수(비선형 변환)의 반복
- **주의**: 행렬 곱만으로는 표현력이 제한됨. 비선형 활성화가 있어야 복잡한 패턴 학습 가능

### 🔑 결국 뭐가 중요한가
1. `y = Wx + b`가 신경망 한 층의 본질
2. 활성화 함수 없이는 깊이가 의미 없다 (아무리 쌓아도 하나의 선형변환)
3. 행렬의 크기가 입력/출력 차원을 결정 → 파라미터 수 결정

## 2-3. Eigenvalue/Eigenvector (고유값/고유벡터)

### 🎯 한 줄 결론
행렬이라는 변환을 가해도 **방향이 안 바뀌는** 특별한 벡터(고유벡터)와, 그때 크기가 몇 배 되는지(고유값)를 말한다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

로드밸런서 비유:
- 트래픽을 서버들에 분배할 때, 어떤 서버는 부하가 크게 변하고 어떤 서버는 거의 안 변한다
- 행렬(변환)을 적용했을 때 **변하지 않는 방향** = 고유벡터
- 그 방향으로 **얼마나 늘어나는지** = 고유값

쉽게 말하면: 행렬은 공간을 찌그러뜨리는데, 고유벡터는 "찌그러져도 방향은 유지되는 축"이다.

→ "남에게 설명한다면: 변환해도 방향이 안 바뀌는 특별한 축을 찾는 것이다. 그 축에서 크기가 얼마나 바뀌는지가 고유값이다."

**[중급 — 어떻게 작동하는가]**

```python
# 고유값 분해의 의미
A @ v = λ * v
# A라는 변환을 v에 적용했더니, 방향은 같고 크기만 λ배가 됐다
# v = 고유벡터, λ = 고유값
```

딥러닝에서 어디에 쓰이는가:
1. **PCA (주성분 분석)**: 데이터의 공분산 행렬의 고유벡터 = 데이터가 가장 많이 퍼진 방향. 고유값이 큰 방향만 남기면 = 차원 축소
2. **Hessian 행렬의 고유값**: loss surface의 곡률(얼마나 급한지). 고유값이 크면 그 방향으로 loss가 급변
3. **Gradient 문제 진단**: RNN에서 가중치 행렬의 최대 고유값 > 1이면 gradient 폭발, < 1이면 소실

→ "남에게 설명한다면: 고유값 분해는 복잡한 변환을 '어느 방향으로 얼마나 늘어나는가'로 분해하는 것이다."

### ⚡ 핵심 요약
- **핵심**: 복잡한 행렬을 "고유한 축들의 신축"으로 분해하는 도구
- **주의**: 고유값이 모두 양수면 양정치(positive definite) → 볼록 함수 → 최솟값이 하나

### 🔑 결국 뭐가 중요한가
1. PCA의 핵심 원리 (차원 축소)
2. 학습 안정성 분석의 도구 (gradient 폭발/소실 진단)
3. Loss surface 분석 (Hessian의 고유값 → flat/sharp minima 판단)

## 2-4. SVD (Singular Value Decomposition, 특이값 분해)

### 🎯 한 줄 결론
아무 행렬이든 **"회전 → 늘리기 → 회전"** 세 단계로 분해할 수 있는 범용 도구다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

고유값 분해는 정방 행렬(n×n)에만 적용 가능하다. 하지만 실제 데이터는 대부분 직사각형 행렬이다 (예: 1000명의 사용자 × 50개 특성). SVD는 **어떤 모양의 행렬에도** 적용 가능한 일반화 버전이다.

```
A = U × Σ × V^T
```
- U: 출력 공간의 회전 (왼쪽 특이벡터)
- Σ: 각 축별 늘리기/줄이기 (특이값 — 대각 행렬)
- V^T: 입력 공간의 회전 (오른쪽 특이벡터)

→ "남에게 설명한다면: 어떤 데이터 변환이든 '방향을 돌리고, 크기를 조절하고, 다시 돌리는' 세 단계로 분해할 수 있다."

### ⚡ 핵심 요약
- **어디에 쓰이는가**: 차원 축소, 데이터 압축, 추천 시스템, 유사역행렬 계산
- **핵심**: 특이값이 큰 것만 남기면 = 핵심 정보만 남김 = 압축/노이즈 제거

### 🔑 결국 뭐가 중요한가
1. 고유값 분해의 일반화 버전 (직사각형 행렬에도 적용 가능)
2. 큰 특이값 = 중요한 정보, 작은 특이값 = 노이즈
3. 실전: Low-Rank Approximation으로 모델 압축에 활용

## 3-1. Gradient (그래디언트)

### 🎯 한 줄 결론
현재 위치에서 **손실(에러)이 가장 가파르게 증가하는 방향**을 가리키는 화살표다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

서버 응답 시간을 최적화한다고 생각해 보자:
- 캐시 TTL을 바꾸면 응답 시간이 어떻게 변하는가?
- DB 커넥션 풀 크기를 바꾸면?
- 스레드 수를 바꾸면?

각 설정을 **조금** 바꿨을 때 성능이 **얼마나** 변하는지가 그 설정에 대한 **편미분**이다.
이 모든 편미분을 하나의 벡터로 모은 것이 **그래디언트**다.

```python
gradient = [
    d(응답시간) / d(캐시TTL),      # 캐시 TTL 변화에 대한 민감도
    d(응답시간) / d(커넥션풀크기),   # 커넥션 풀 변화에 대한 민감도
    d(응답시간) / d(스레드수),       # 스레드 수 변화에 대한 민감도
]
```

그래디언트의 **반대 방향**으로 설정을 바꾸면 응답 시간이 줄어든다 → 이것이 **경사 하강법**.

→ "남에게 설명한다면: 각 설정이 결과에 미치는 영향을 계산해서, 결과를 가장 빠르게 개선하는 방향으로 설정을 바꾸는 것이다."

### ⚡ 핵심 요약
- **핵심**: 그래디언트 = "어디로 가면 에러가 가장 빨리 줄어드는가"를 알려주는 나침반
- **주의**: 그래디언트는 **현재 위치에서의 국소적** 정보만 제공. 전체 지형을 보는 게 아님

### 🔑 결국 뭐가 중요한가
1. 딥러닝 학습의 핵심 = 그래디언트 계산 → 파라미터 업데이트
2. 그래디언트가 0인 곳 = 극소/극대/안장점 (평평한 곳)
3. 그래디언트의 크기 = 학습할 여지가 얼마나 남았는지

## 3-2. Chain Rule (연쇄 법칙) / Backpropagation (역전파)

### 🎯 한 줄 결론
여러 단계의 함수가 연결됐을 때, 최종 에러의 원인을 **역순으로 추적**하는 규칙이다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

프로덕션 장애의 원인 추적을 생각해 보자:

```
사용자 요청 → API Gateway → Auth Service → DB → 에러 발생!
```

에러가 최종 응답에 미친 영향을 역추적:
1. DB의 타임아웃이 → Auth 응답 지연에 기여한 정도
2. Auth 지연이 → API Gateway 타임아웃에 기여한 정도
3. 전체 영향 = 각 단계의 기여도를 **곱한 것**

이것이 **연쇄 법칙**이다:
```
전체 영향 = (DB→Auth 영향) × (Auth→Gateway 영향) × (Gateway→최종 영향)
```

**역전파(Backpropagation)**는 이 연쇄 법칙을 신경망에 적용한 것이다:
1. 순전파: 입력 → 출력 계산 (서비스 호출)
2. 손실 계산: 출력과 정답의 차이 (에러 감지)
3. 역전파: 각 층의 가중치가 에러에 얼마나 기여했는지 **역순으로** 계산 (에러 로그 역추적)
4. 파라미터 업데이트: 기여도에 비례해서 가중치 조정 (설정 수정)

→ "남에게 설명한다면: 역전파는 에러 로그를 역순으로 따라가면서, 각 서비스(층)가 에러에 얼마나 기여했는지 계산하고, 그에 비례해서 설정을 고치는 것이다."

### ⚡ 핵심 요약
- **핵심**: 역전파 = 연쇄 법칙의 효율적 구현. 각 층의 그래디언트를 뒤에서 앞으로 전파
- **주의**: 층이 깊으면 곱셈이 반복되면서 기울기가 소실(vanishing)하거나 폭발(exploding)할 수 있음

### 🔑 결국 뭐가 중요한가
1. 딥러닝 학습 = 순전파 + 역전파 반복
2. 역전파의 본질 = 연쇄 법칙(체인 룰)을 뒤에서 앞으로 적용
3. Vanishing gradient 문제의 원인 = 이 곱셈 체인에서 값이 점점 작아짐

## 3-3. SGD / Momentum / Adam (최적화 알고리즘)

### 🎯 한 줄 결론
산에서 내려가는 다양한 전략이다. SGD는 기본, Momentum은 관성 추가, Adam은 지형에 적응하는 버전이다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

서버 설정 최적화를 자동화하는 세 가지 방식:

**SGD (Stochastic Gradient Descent)**: 매번 요청 샘플 몇 개만 보고 설정 조정
- 장점: 빠름
- 단점: 방향이 들쭉날쭉 (노이즈가 많음)

**Momentum**: SGD + 관성. 이전에 가던 방향을 기억
- 비유: 공이 언덕을 굴러 내려갈 때 관성으로 작은 언덕은 넘어감
- 장점: 지그재그 줄어듦, 수렴 빨라짐

**Adam**: Momentum + 각 파라미터별 학습률 자동 조정
- 비유: 지형을 학습하는 자율주행차. 가파른 길에서는 조심히, 평탄한 길에서는 빠르게
- 실전에서 **가장 많이 사용**. 대부분의 경우 좋은 기본값

```python
# 핵심 차이
SGD:      params -= learning_rate * gradient
Momentum: velocity = 0.9 * velocity + gradient
          params -= learning_rate * velocity
Adam:     # 1차 모멘트(평균) + 2차 모멘트(분산) 추적
          # 각 파라미터의 업데이트 크기를 자동 조절
```

→ "남에게 설명한다면: SGD는 매번 눈치껏 한 발짝, Momentum은 관성 달린 공, Adam은 지형을 학습하는 똑똑한 공이다."

### ⚡ 핵심 요약
- **핵심**: Adam이 기본값으로 가장 많이 쓰이지만, SGD+Momentum이 일반화에서 더 좋을 수 있음
- **주의**: 학습률(learning rate)이 가장 중요한 하이퍼파라미터. 알고리즘보다 학습률 튜닝이 더 중요할 때가 많음

### 🔑 결국 뭐가 중요한가
1. Adam = 실전의 안전한 기본값
2. SGD + Momentum = 연구에서 일반화 성능이 더 좋은 경우가 많음
3. 어떤 알고리즘이든 학습률이 가장 중요한 설정값

---

## 3-4. Jacobian / Hessian (야코비안 / 헤시안)

### 🎯 한 줄 결론
Jacobian은 1차 미분(기울기)을 행렬로, Hessian은 2차 미분(곡률)을 행렬로 정리한 것이다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

**Jacobian (야코비안)**: 여러 입력 → 여러 출력인 함수의 "민감도 맵"

마이크로서비스 의존성을 생각해 보자:
```
Service A, B, C → 영향 → Metric X, Y
```
- A가 1% 바뀌면 X가 몇 % 바뀌고 Y가 몇 % 바뀌는가?
- B가 1% 바뀌면? C가 1% 바뀌면?
- 이 모든 관계를 표로 정리한 것 = Jacobian 행렬

**Hessian (헤시안)**: 기울기가 얼마나 빠르게 변하는지 = **지형의 곡률**

- 그래디언트가 "어느 방향이 내리막인지" 알려준다면
- 헤시안은 "그 내리막이 얼마나 급한지, 얼마나 구불구불한지" 알려준다
- Hessian의 고유값이 크면 = 그 방향으로 loss가 급격히 변함 (뾰족한 골짜기)
- Hessian의 고유값이 작으면 = 그 방향으로 loss가 완만 (평탄한 골짜기)

→ "남에게 설명한다면: Jacobian은 '각 입력이 각 출력에 미치는 영향 표'이고, Hessian은 '지형이 얼마나 구불구불한지'를 알려주는 표다."

### ⚡ 핵심 요약
- **어디에 쓰이는가**: Jacobian → 역전파의 핵심. Hessian → 최적화 분석, flat/sharp minima 판단
- **주의**: Hessian은 파라미터 수의 제곱 크기 → 실제로 계산하기 어려움 → 근사 방법 사용

### 🔑 결국 뭐가 중요한가
1. Jacobian = 역전파에서 각 층의 그래디언트 전달 도구
2. Hessian = loss surface의 곡률 분석 (flat/sharp minima)
3. 둘 다 직접 계산하기엔 비용이 큼 → 실전에서는 근사 기법 사용

## 4-1. 확률 분포 핵심 (Bernoulli / Gaussian / i.i.d.)

### 🎯 한 줄 결론
데이터가 어떤 패턴으로 나타나는지를 수학적으로 모델링한 것이 확률 분포이다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

API 응답 시간 데이터를 모니터링한다고 생각해 보자:
- 대부분 50ms 근처에 모이고, 가끔 100ms, 아주 드물게 500ms → 이 패턴이 **분포**
- 이 패턴을 수학적으로 표현하면 → 예측과 이상 탐지가 가능해진다

**베르누이(Bernoulli)**: 성공/실패 두 가지만 있는 경우
- 비유: API 호출의 성공/실패, 사용자의 클릭/미클릭
- 파라미터 하나: 성공 확률 p

**가우시안(Gaussian, 정규분포)**: 종 모양 곡선. 자연에서 가장 흔한 분포
- 비유: API 응답 시간 분포, 사용자 활동량 분포
- 파라미터 두 개: 평균(μ)과 분산(σ²)

**i.i.d. (independent and identically distributed)**: "각 데이터가 같은 조건에서 독립적으로 생성됐다"
- 비유: 각 API 요청이 서로 영향을 주지 않고, 모두 같은 서버 조건에서 처리된다고 가정
- 거의 모든 ML 모델의 기본 가정. 시계열 데이터 등에서는 이 가정이 깨짐

→ "남에게 설명한다면: 확률 분포는 데이터의 패턴을 수학적으로 표현한 것이다. 딥러닝은 이 패턴을 학습하는 것이다."

### ⚡ 핵심 요약
- **핵심**: 딥러닝의 모든 것은 확률 분포 위에 세워져 있다 (데이터 분포, 모델 출력, 가중치 초기화)
- **주의**: i.i.d. 가정이 깨지는 상황을 인지해야 함 (시계열, 강화학습 등)

### 🔑 결국 뭐가 중요한가
1. Bernoulli → 이진 분류의 기초 (sigmoid 출력)
2. Gaussian → 가중치 초기화, 노이즈 모델링, VAE의 기초
3. i.i.d. 가정 = ML의 기본 전제. 깨지면 특별한 처리 필요

## 4-2. Expectation / Variance / Covariance (기댓값 / 분산 / 공분산)

### 🎯 한 줄 결론
기댓값은 **평균**, 분산은 **흩어진 정도**, 공분산은 **두 변수가 함께 움직이는 정도**다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

서비스 메트릭 모니터링 비유:

**기댓값 = 평균 응답 시간**
- 전체 요청의 평균적인 응답 시간. "보통 이 정도 걸린다"

**분산 = 응답 시간의 들쭉날쭉한 정도**
- 분산이 작다: 항상 50ms 근처 → 예측 가능, 안정적
- 분산이 크다: 10ms~500ms까지 널뜀 → 불안정

**공분산 = 두 메트릭이 함께 움직이는 정도**
- CPU 사용률과 응답 시간의 공분산이 양수 → CPU가 올라가면 응답도 느려짐
- 캐시 히트율과 응답 시간의 공분산이 음수 → 캐시가 높으면 응답이 빨라짐
- 공분산 ≈ 0 → 두 지표가 서로 관련 없음

딥러닝에서:
- 기댓값: 손실 함수의 기대값을 최소화하는 것이 학습 목표
- 분산: 모델 예측의 분산이 크면 불안정 (Bias-Variance Tradeoff)
- 공분산: 특성들 간의 관계를 이해하는 데 사용 (PCA 등)

→ "남에게 설명한다면: 기댓값은 '보통 어떤 값', 분산은 '얼마나 들쭉날쭉한지', 공분산은 '두 것이 같이 움직이는지'를 숫자로 표현한 것이다."

### ⚡ 핵심 요약
- **핵심**: 이 세 가지로 데이터의 핵심 특성을 요약할 수 있다
- **주의**: 공분산 = 0이 "독립"을 의미하지는 않는다 (선형 관계만 측정)

### 🔑 결국 뭐가 중요한가
1. 손실 함수의 기대값 최소화 = 딥러닝 학습의 수학적 정의
2. 분산 = 모델 안정성의 척도 (Bias-Variance Tradeoff)
3. 공분산 행렬 = PCA, 가우시안 분포, Batch Normalization의 기초

## 5-1. Entropy (엔트로피) / Cross-Entropy (교차 엔트로피)

### 🎯 한 줄 결론
엔트로피는 **불확실성의 양**이고, 교차 엔트로피는 **모델이 현실을 얼마나 잘못 표현하는지**의 척도다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

로그 압축 시스템 비유:

**엔트로피 = 로그 메시지를 최적으로 압축했을 때 필요한 최소 비트 수**
- 로그의 99%가 "OK"이고 1%만 "ERROR"라면 → 불확실성이 낮음 → 적은 비트로 압축 가능
- "OK"와 "ERROR"가 반반이면 → 불확실성 최대 → 더 많은 비트 필요

**교차 엔트로피 = 잘못된 압축 코드를 썼을 때 낭비되는 비트 수**
- 실제로는 "OK" 99%인데, 모델이 "50:50"이라고 가정하고 압축하면 → 비트 낭비 발생
- 모델의 가정이 현실과 가까울수록 → 낭비가 줄어듦 → 교차 엔트로피가 작아짐

딥러닝에서 교차 엔트로피 손실함수:
```python
# 정답: "고양이" (클래스 2), 모델 출력: [0.1, 0.05, 0.7, 0.15]
loss = -log(0.7)  # ≈ 0.36

# 만약 모델이 확신 없이 [0.25, 0.25, 0.25, 0.25]를 출력했다면
loss = -log(0.25)  # ≈ 1.39 (훨씬 큰 손실)
```

→ "남에게 설명한다면: 교차 엔트로피는 모델이 정답에 높은 확률을 줬는지를 측정한다. 정답에 낮은 확률을 주면 큰 페널티를 받는다."

**[중급 — 어떻게 작동하는가]**

핵심 관계:
```
교차 엔트로피 = 엔트로피 + KL Divergence
H(P, Q) = H(P) + D_KL(P || Q)
```

이 수식이 말하는 것은:
- H(P) = 데이터 자체의 불확실성 (바꿀 수 없는 부분)
- D_KL(P || Q) = 모델과 현실 사이의 차이 (줄여야 하는 부분)
- 교차 엔트로피를 최소화 = KL Divergence를 최소화 = **모델을 현실에 가깝게**

MSE 대신 교차 엔트로피를 쓰는 이유:
- Sigmoid/Softmax 출력이 극단값(0이나 1 근처)일 때, MSE는 기울기가 거의 0 → 학습 안 됨
- 교차 엔트로피는 이 상황에서도 큰 기울기 유지 → 학습이 빠름

→ "남에게 설명한다면: 분류 문제에서 교차 엔트로피를 쓰는 이유는 모델이 틀렸을 때 더 강한 교정 신호를 주기 때문이다."

### ⚡ 핵심 요약
- **핵심**: 분류 문제의 사실상 표준 손실함수 = 교차 엔트로피
- **주의**: 교차 엔트로피 최소화 = KL Divergence 최소화 (H(P)는 상수이므로)

### 🔑 결국 뭐가 중요한가
1. 엔트로피 = 불확실성. 높으면 예측이 어려움
2. 교차 엔트로피 = 분류의 표준 손실함수. 모델과 정답의 거리
3. KL Divergence = 두 분포의 차이. VAE, 지식 증류 등에서 핵심

## 5-2. KL Divergence (KL 발산) / Mutual Information (상호 정보량)

### 🎯 한 줄 결론
KL Divergence는 **두 확률 분포가 얼마나 다른지**, Mutual Information은 **두 변수가 얼마나 정보를 공유하는지** 측정한다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

**KL Divergence** — A/B 테스트 비유:
- 기존 버전(P)의 클릭 분포와 신규 버전(Q)의 클릭 분포가 얼마나 다른가?
- KL(P||Q) = 0이면 → 완전히 같은 분포
- 클수록 → 두 분포가 많이 다름
- **비대칭**: KL(P||Q) ≠ KL(Q||P). "P 관점에서 Q가 얼마나 다른가"와 "Q 관점에서 P가 얼마나 다른가"가 다름

**Mutual Information** — 상관관계를 넘어선 의존성 측정:
- "사용자의 접속 시간을 알면, 구매 여부를 얼마나 더 잘 예측할 수 있는가?"
- 0이면 → 완전히 독립 (아무 정보도 공유 안 함)
- 클수록 → 한 변수가 다른 변수에 대한 정보를 많이 담고 있음

→ "남에게 설명한다면: KL은 두 분포의 차이, MI는 두 변수가 공유하는 정보량이다."

### ⚡ 핵심 요약
- **어디에 쓰이는가**: KL → VAE 손실함수, 지식 증류, 정책 학습. MI → 특성 선택, 표현 학습
- **주의**: KL은 거리(distance)가 아니다 — 비대칭이고 삼각 부등식 불만족

### 🔑 결국 뭐가 중요한가
1. KL Divergence = 모델 분포를 데이터 분포에 가깝게 만드는 학습 신호
2. Mutual Information = 두 변수 사이의 정보적 연결. 공분산보다 일반적
3. KL은 비대칭이라 방향에 따라 의미가 다름 (forward KL vs reverse KL)

## 6-1. Bayes' Theorem (베이즈 정리) 상세

### 🎯 한 줄 결론
새로운 증거(데이터)를 보고 **기존 믿음을 업데이트**하는 공식이다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

온콜 장애 대응 비유:

1. **사전 확률 (Prior)**: 과거 통계로 볼 때, 장애의 60%가 네트워크, 30%가 DB, 10%가 앱 버그
2. 새로운 **증거**: 에러 로그에 "connection timeout"이 찍힘
3. **우도 (Likelihood)**:
   - 네트워크 문제일 때 이 로그가 나올 확률: 80%
   - DB 문제일 때: 40%
   - 앱 버그일 때: 5%
4. **사후 확률 (Posterior)**: 증거를 반영한 업데이트된 확률
   - 네트워크: 0.6 × 0.8 = 0.48 → 정규화 후 ≈ 78%
   - DB: 0.3 × 0.4 = 0.12 → ≈ 20%
   - 앱 버그: 0.1 × 0.05 = 0.005 → ≈ 1%

핵심: **사전 지식 + 새 증거 = 업데이트된 판단**

```
사후확률 = (우도 × 사전확률) / 증거
posterior ∝ likelihood × prior
```

→ "남에게 설명한다면: 새로운 증거가 들어올 때마다, 이전의 믿음에 증거를 곱해서 믿음을 업데이트하는 것이 베이즈 추론이다."

### ⚡ 핵심 요약
- **핵심**: 데이터가 쌓일수록 사전확률의 영향이 줄고, 우도(데이터)의 영향이 커짐
- **어디에 쓰이는가**: MLE/MAP의 근간, 베이지안 딥러닝, 불확실성 추정

### 🔑 결국 뭐가 중요한가
1. Prior(사전 지식)이 적절하면 적은 데이터로도 좋은 판단 가능
2. 데이터가 충분하면 prior의 영향이 사라짐 (MLE ≈ MAP)
3. 딥러닝의 정규화 = "가중치는 작은 게 좋다"는 prior를 넣은 것

## 6-2. Conjugate Prior (켤레 사전분포) / Beta Distribution (베타 분포)

### 🎯 한 줄 결론
사후분포가 사전분포와 **같은 종류**가 되게 하는 편리한 사전분포 선택이다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

설정 관리 시스템 비유:
- 설정 형식이 JSON으로 들어왔는데, 업데이트 후에도 JSON으로 나오면 편리하다
- 만약 업데이트할 때마다 형식이 YAML → XML → TOML로 바뀌면? → 처리 로직이 복잡해짐

**켤레 사전분포**도 같은 개념:
- Beta 분포를 prior로 → 데이터(베르누이)를 관찰 후 → posterior도 Beta 분포
- 업데이트가 단순한 파라미터 수정으로 끝남

**Beta 분포**: 0~1 사이 확률값의 분포
- Beta(a, b)에서 a = "이전에 본 성공 횟수 + 1", b = "이전에 본 실패 횟수 + 1"
- Beta(1, 1) = 균등분포 (아무 정보 없음)
- Beta(100, 100) = 0.5에 강하게 집중 (확신 강함)

→ "남에게 설명한다면: 입력과 출력의 형식이 같으면 반복 업데이트가 쉽듯, 켤레 사전분포는 업데이트 전후의 분포 형태를 같게 유지해주는 편리한 선택이다."

### ⚡ 핵심 요약
- **핵심**: 계산 편의성을 위한 수학적 장치. 실용적으로는 대규모 모델에서 잘 안 쓰임
- **주의**: 켤레 prior가 항상 가장 적절한 사전 지식은 아님

### 🔑 결국 뭐가 중요한가
1. 켤레 prior = 베이즈 업데이트를 닫힌 형태(closed-form)로 계산 가능하게 해줌
2. Beta-Bernoulli 켤레쌍이 시험에 가장 많이 나옴
3. 실전 딥러닝에서는 변분 추론 등 근사 방법이 더 일반적

## 7-1. Supervised / Unsupervised / Reinforcement Learning

### 🎯 한 줄 결론
지도학습은 **정답지 있는 공부**, 비지도학습은 **정답 없이 패턴 찾기**, 강화학습은 **시행착오로 전략 학습**이다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

| 패러다임 | 백엔드 비유 | 핵심 |
|---------|-----------|------|
| **지도학습** | 테스트 코드(정답)를 보고 구현하기 | 입력-정답 쌍으로 학습 |
| **비지도학습** | 로그를 분석해서 알아서 패턴 분류하기 | 정답 없이 구조 발견 |
| **강화학습** | A/B 테스트로 최적 설정 찾기 (보상 기반) | 보상 신호로 전략 학습 |

**지도학습** 세부:
- 분류(Classification): 이메일 → 스팸/정상 (이산적 레이블)
- 회귀(Regression): 집 특성 → 가격 예측 (연속적 값)

**비지도학습** 세부:
- 군집화(Clustering): 사용자를 행동 패턴별로 그룹핑
- 차원 축소: 100개 특성 → 핵심 10개로 압축
- 생성 모델: 새로운 데이터 생성 (GAN, VAE)

→ "남에게 설명한다면: 정답을 주고 학습시키면 지도학습, 데이터만 주고 알아서 패턴을 찾게 하면 비지도학습, 보상으로 시행착오를 거치면 강화학습이다."

### ⚡ 핵심 요약
- **핵심**: 대부분의 실용 딥러닝은 지도학습 + 최근에는 자기지도학습(self-supervised)이 대세
- **연구 포인트**: Self-Supervised Learning = 비지도학습과 지도학습의 경계를 무너뜨림

### 🔑 결국 뭐가 중요한가
1. 지도학습 = 가장 성숙하고 실용적
2. 자기지도학습(GPT, BERT 등) = 레이블 없이도 강력한 표현 학습
3. 강화학습 = RLHF(ChatGPT 훈련)에서 핵심 역할

## 7-2. Loss Function / ERM / Overfitting / Regularization

### 🎯 한 줄 결론
손실함수는 **모델이 얼마나 틀렸는지의 점수**이고, 정규화는 **과적합을 방지하는 제동장치**다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

**손실함수 = API 모니터링의 에러율 지표**
```python
# 회귀용 (MSE): 예측과 정답의 차이 제곱 평균
mse = mean((predicted - actual) ** 2)

# 분류용 (Cross-Entropy): 정답 클래스에 부여한 확률의 -log
ce = -log(model_output[correct_class])
```

**ERM (Empirical Risk Minimization) = "훈련 데이터에서 평균 손실을 최소화하자"**
- 비유: 기존 트래픽 패턴에서 최적 설정을 찾는 것
- 문제: 기존 패턴에만 최적화하면 새 패턴에서 망할 수 있음

**과적합 = 훈련 데이터의 노이즈까지 학습한 상태**
- 비유: 특정 사용자의 이상한 접속 패턴에 맞춰 서버를 최적화한 것

**정규화 = 과적합 방지 제동장치**
| 기법 | 비유 | 효과 |
|------|------|------|
| L2 정규화 | 코드 복잡도 제한 (lint 룰) | 가중치가 너무 커지는 것 방지 |
| Dropout | 랜덤으로 팀원 빼고 돌리기 | 특정 뉴런 의존 방지 |
| Early Stopping | 모니터링하다가 악화되면 배포 중단 | 학습 시간 제한 |
| Data Augmentation | 테스트 케이스 변형해서 늘리기 | 데이터 다양성 증가 |

→ "남에게 설명한다면: 손실함수로 모델의 에러를 측정하고, 정규화로 훈련 데이터에만 과도하게 맞추는 것을 방지한다."

### ⚡ 핵심 요약
- **핵심**: 학습 = 손실함수 최소화. 일반화 = 정규화로 과적합 방지
- **주의**: 정규화 강도가 너무 크면 과소적합(underfitting) 발생

### 🔑 결국 뭐가 중요한가
1. MSE는 회귀, Cross-Entropy는 분류의 표준 손실함수
2. ERM + 정규화 = 현대 ML의 기본 프레임워크
3. 훈련 에러가 낮은 것보다 검증 에러가 낮은 것이 중요

## 8-1. Activation Function (활성화 함수)

### 🎯 한 줄 결론
신경망에 **비선형성**을 부여하여 복잡한 패턴을 학습할 수 있게 하는 함수다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

미들웨어 파이프라인에서 만약 모든 미들웨어가 "입력에 상수를 곱하고 더하기"만 한다면:
```python
# 미들웨어 1: y = 2x + 1
# 미들웨어 2: y = 3x + 2
# 합치면: y = 3(2x + 1) + 2 = 6x + 5 → 결국 하나의 "ax + b"
```

아무리 미들웨어를 많이 쌓아도 **선형 변환 하나**와 같다. 이래서는 직선밖에 그리지 못한다.

활성화 함수는 각 미들웨어 뒤에 붙는 **비선형 변환**이다:

| 이름 | 동작 | 비유 |
|------|------|------|
| **ReLU** | 음수 → 0, 양수 → 그대로 | if 문: `max(0, x)` |
| **Sigmoid** | 아무 값 → 0~1 사이로 압축 | 확률로 변환하는 정규화 |
| **Tanh** | 아무 값 → -1~1 사이로 압축 | 영점 중심 정규화 |
| **GELU** | ReLU의 부드러운 버전 | Transformer에서 사용 |

→ "남에게 설명한다면: 활성화 함수는 신경망이 곡선을 그릴 수 있게 해주는 핵심 장치다. 없으면 아무리 깊어도 직선밖에 못 그린다."

### ⚡ 핵심 요약
- **핵심**: ReLU가 현재 기본값. 단순하고 빠르고 gradient vanishing 적음
- **주의**: ReLU의 "죽은 뉴런" 문제 — 한 번 0이 되면 영원히 0 → Leaky ReLU로 해결

### 🔑 결국 뭐가 중요한가
1. 활성화 함수 없이는 깊이가 무의미하다
2. 실전 기본: 은닉층은 ReLU, 이진 분류 출력은 Sigmoid, 다중 분류 출력은 Softmax
3. Transformer 계열에서는 GELU가 표준

## 8-2. Vanishing / Exploding Gradient (기울기 소실 / 폭발)

### 🎯 한 줄 결론
역전파 시 기울기가 층을 거치면서 **0에 수렴하거나 무한대로 발산**하는 문제다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

전화 게임(Chinese whispers) 비유:
- 10명이 한 줄로 서서 메시지를 전달
- 매번 전달 시 메시지가 살짝 줄어든다면 (×0.9) → 마지막 사람: 0.9^10 ≈ 0.35 (소실)
- 매번 살짝 커진다면 (×1.1) → 마지막 사람: 1.1^10 ≈ 2.59 (폭발)

역전파에서도 동일한 일이 벌어진다:
```
최종 에러 → [층10 기울기] × [층9 기울기] × ... × [층1 기울기] = 최초 층의 기울기
```

기울기가 계속 곱해지므로:
- 각 값이 < 1이면 → 지수적으로 0에 수렴 → **소실** → 앞쪽 층이 학습 안 됨
- 각 값이 > 1이면 → 지수적으로 폭발 → **폭발** → 학습 발산

**해결책들**:
| 해결책 | 메커니즘 |
|--------|---------|
| ReLU 사용 | 양수 영역에서 기울기 = 1 (감쇠 없음) |
| Skip Connection (ResNet) | 기울기가 직통 경로로도 전달됨 |
| 적절한 초기화 (Xavier, He) | 각 층의 출력 분산을 1로 유지 |
| Batch Normalization | 각 층의 출력을 정규화 |
| Gradient Clipping | 기울기 크기 제한 (폭발 방지) |

→ "남에게 설명한다면: 역전파는 곱셈의 연쇄인데, 이 곱이 계속 줄어들거나 커지면 학습이 안 된다. 이를 해결하려고 ReLU, Skip Connection 등이 등장했다."

### ⚡ 핵심 요약
- **핵심**: 딥러닝이 "딥"하기 어려웠던 근본 원인. 이것의 해결이 딥러닝 혁명의 핵심
- **주의**: Gradient clipping은 폭발만 방지. 소실은 아키텍처로 해결해야 함

### 🔑 결국 뭐가 중요한가
1. Vanishing gradient = 깊은 네트워크 학습의 가장 큰 장벽이었음
2. ReLU + Skip Connection + BatchNorm = 이 문제를 해결한 3대 혁신
3. LSTM의 Cell State, Transformer의 Residual Connection 모두 이 문제의 해결책

## 9-1. Bias-Variance Tradeoff

### 🎯 한 줄 결론
모델이 **너무 단순하면 편향**(Bias)이 높고, **너무 복잡하면 분산**(Variance)이 높다. 이 균형을 잡는 것이 핵심이다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

서버 오토스케일링 정책 비유:
- **Bias 높음** = 항상 서버 2대 고정. 단순하지만 트래픽 변화에 대응 못 함 (과소적합)
- **Variance 높음** = 1초 단위로 트래픽에 반응. 민감하지만 노이즈에 휘둘림 (과적합)
- **최적** = 적절한 반응 주기와 임계값 설정

```
예측 오차 = Bias² + Variance + 줄일 수 없는 노이즈
```

이 수식이 말하는 것은: "전체 에러는 세 가지로 나뉘는데, Bias와 Variance는 트레이드오프 관계고, 노이즈는 어쩔 수 없다."

→ "남에게 설명한다면: 모델을 너무 단순하게 만들면 유연성이 부족하고, 너무 복잡하게 만들면 노이즈에 휘둘린다. 적절한 복잡도를 찾는 게 핵심이다."

### ⚡ 핵심 요약
- **핵심**: 전통적 ML의 핵심 원리. 하지만 딥러닝에서는 Double Descent로 이 관점이 확장됨
- **주의**: 현대 딥러닝은 Bias도 낮고 Variance도 낮은 영역이 있음 (과매개변수화)

### 🔑 결국 뭐가 중요한가
1. 모델 복잡도의 "적정선"을 찾는 프레임워크
2. Bias ↑ = 과소적합, Variance ↑ = 과적합
3. 딥러닝에서는 이 트레이드오프가 단순하지 않음 (Double Descent)

## 9-2. Flat Minima vs Sharp Minima / SAM

### 🎯 한 줄 결론
넓고 평평한 골짜기에 도달한 모델이 뾰족한 골짜기보다 **실전에서 잘 작동**한다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

배포 환경 안정성 비유:
- **Flat minimum**: 설정값이 조금 바뀌어도 서비스가 안정적. "여유 있는 최적"
- **Sharp minimum**: 설정값이 조금만 바뀌어도 서비스가 불안정. "아슬아슬한 최적"

프로덕션에서는 항상 약간의 변동이 있다 (데이터 분포 변화, 노이즈 등). 그래서 flat minimum이 일반화가 좋다.

**SAM (Sharpness-Aware Minimization)**:
- 보통의 학습: "현재 위치에서 loss를 줄여라"
- SAM: "현재 위치 **주변에서 가장 나쁜 경우**의 loss를 줄여라"
- 비유: "최악의 트래픽 시나리오에서도 버티는 설정을 찾아라"

→ "남에게 설명한다면: 최적 설정이 여유 있는 것(flat)이 아슬아슬한 것(sharp)보다 안정적이듯, 딥러닝도 넓은 골짜기의 바닥을 찾는 것이 좋다."

### ⚡ 핵심 요약
- **핵심**: SGD가 flat minima를 선호하는 경향이 있어서, 일반화에 좋다
- **연구 포인트**: SAM은 flat minima를 직접 찾는 알고리즘. 비용이 2배지만 성능 향상

### 🔑 결국 뭐가 중요한가
1. Flat minimum = 좋은 일반화, Sharp minimum = 나쁜 일반화
2. 작은 배치 사이즈의 SGD가 flat minima로 가는 경향
3. SAM = flat minima를 명시적으로 찾는 최적화 방법

## 9-3. Implicit Regularization / Grokking / Lottery Ticket

### 🎯 한 줄 결론
SGD는 정규화 없이도 자동으로 **간단한 해를 선호**하고(Implicit Regularization), 모델은 **한참 뒤에야 일반화**하기도 하며(Grokking), 큰 모델 안에는 **작지만 효과적인 서브모델**이 숨어있다(Lottery Ticket).

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

**Implicit Regularization (암묵적 정규화)**:
- 비유: Git이 merge할 때 자동으로 가장 단순한 병합 전략을 선택하는 것
- SGD는 명시적 정규화(L2 등) 없이도 자동으로 복잡하지 않은 해를 선호
- 왜? SGD의 노이즈가 sharp minima에서 탈출하게 만들어서

**Grokking (그로킹)**:
- 비유: 수학 공식을 외워서 시험을 통과한 후(훈련 100%), 한참 뒤에야 "아! 이게 이런 뜻이구나" 깨달음이 오는 것(테스트 100%)
- 훈련 정확도가 이미 100%인데, 수만 에폭 뒤에야 갑자기 테스트 정확도가 올라감

**Lottery Ticket Hypothesis (복권 가설)**:
- 비유: 1000명의 팀에서 실제로 핵심 업무를 하는 50명짜리 팀을 찾는 것
- 큰 네트워크 안에 작은 "당첨 서브네트워크"가 있고, 그것만으로도 같은 성능 달성 가능
- 모델 압축(pruning)의 이론적 근거

→ "남에게 설명한다면: 딥러닝은 정규화를 넣지 않아도 어느 정도 스스로 과적합을 방지하고(Implicit Regularization), 한참 뒤에야 갑자기 깨달음을 얻기도 하며(Grokking), 실제로 필요한 파라미터는 전체의 일부분이다(Lottery Ticket)."

### ⚡ 핵심 요약
- **연구 포인트**: 세 가지 모두 "왜 과매개변수화된 딥러닝이 잘 작동하는가"를 설명하려는 시도
- **실용적 의미**: Lottery Ticket → 모델 압축/경량화에 직접 활용

### 🔑 결국 뭐가 중요한가
1. 과매개변수화가 작동하는 이유 = Implicit Regularization + 학습 동역학
2. Grokking = "훈련 완료 ≠ 일반화 완료". 정규화를 오래 돌려야 할 수도
3. Lottery Ticket = 모델을 줄이는 것은 가능하지만, 큰 모델로 시작해야 찾을 수 있음

## 10-1. Convolution / Kernel / Feature Map

### 🎯 한 줄 결론
작은 패턴 감지기(커널)를 이미지 위에서 **슬라이딩**하며 특정 패턴을 찾아내는 연산이다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

텍스트 로그에서 패턴 매칭하는 `grep`을 생각해 보자:
- `grep "ERROR"` → 로그 전체를 훑으면서 "ERROR" 패턴을 찾는다
- 발견된 위치를 표시한 결과 = Feature Map

CNN의 합성곱도 동일한 원리:
- **커널(필터)** = 찾고 싶은 패턴 (예: 수평 엣지, 대각선 등)
- **슬라이딩** = 이미지의 모든 위치에서 패턴 매칭
- **Feature Map** = 각 위치에서 패턴이 얼마나 매칭되는지의 지도

Fully Connected와의 차이:
- FC: 모든 입력과 모든 출력이 연결 → 위치 정보 무시, 파라미터 폭발
- CNN: 작은 커널을 **공유**하며 슬라이딩 → 위치 정보 보존, 파라미터 효율적

```python
# 비유: grep vs 전수조사
# FC = 전수조사: 모든 로그 라인에 대해 독립적인 규칙 적용
# CNN = grep: 하나의 패턴을 전체에 대해 슬라이딩
```

→ "남에게 설명한다면: CNN은 작은 패턴 감지기를 이미지 전체에서 슬라이딩하며, 그 패턴이 어디에 있는지 지도(feature map)를 만드는 것이다."

### ⚡ 핵심 요약
- **핵심**: Parameter Sharing(가중치 공유)으로 파라미터 효율적 + Translation Equivariance(위치 불변)
- **주의**: Conv 출력 크기 = `(입력 + 2×패딩 - 커널) / 스트라이드 + 1`

### 🔑 결국 뭐가 중요한가
1. 커널 = 학습 가능한 패턴 감지기. 사람이 설계하지 않고 데이터에서 자동 학습
2. 가중치 공유 = 적은 파라미터로 효율적 처리
3. 깊이에 따라 저수준(엣지) → 고수준(물체) 특징이 계층적으로 학습됨

## 10-2. ResNet / Skip Connection

### 🎯 한 줄 결론
입력을 몇 층 **건너뛰어** 출력에 직접 더함으로써, 아무리 깊어도 학습이 가능하게 만든 구조다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

마이크로서비스 장애 전파 방지 비유:
- 서비스 A → B → C → D → E 순차 호출
- C가 느려지면 전체가 느려짐 (= gradient vanishing)
- **해결**: A → E 직통 경로(skip connection)를 추가. C가 느려도 최소한 A의 데이터가 E에 도달

```
x ──────────────────────(+)──→ y
    │                    ↑
    └→ Conv → BN → ReLU → Conv → BN ─┘

y = F(x) + x  ← "원본 + 변화량"
```

핵심 직관:
- 네트워크가 `F(x) = 0`을 학습하면 → `y = x` (항등 함수)
- 즉, 층을 추가해도 **최악의 경우에도 아무 것도 안 하는 것**이 보장됨
- "변환 전체를 학습"하는 게 아니라 "변화량(residual)만 학습" → 훨씬 쉬움

→ "남에게 설명한다면: 직통 경로를 추가해서, 실패해도 원본 데이터가 살아남게 한 것이다. 덕분에 100층 이상 쌓아도 학습이 가능해졌다."

### ⚡ 핵심 요약
- **핵심**: Gradient가 skip connection을 통해 직접 전파 → vanishing gradient 해결
- **어디에 쓰이는가**: ResNet, Transformer, U-Net 등 거의 모든 현대 아키텍처

### 🔑 결국 뭐가 중요한가
1. Skip Connection = 딥러닝에서 가장 중요한 아키텍처 혁신 중 하나
2. "전체 변환" 대신 "변화량"을 학습 → 학습이 훨씬 쉬워짐
3. Transformer의 Residual Connection도 같은 원리

## 10-3. Stride / Padding / Pooling / 1x1 Conv / Depthwise Separable

### 🎯 한 줄 결론
CNN의 다양한 빌딩 블록들로, 출력 크기 조절, 채널 조절, 연산량 절약 등의 역할을 한다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

| 구성요소 | 비유 | 역할 |
|---------|------|------|
| **Stride** | grep에서 몇 줄씩 건너뛰며 검색 | 커널 이동 간격. 2면 출력 절반 |
| **Padding** | 문자열 양끝에 공백 추가 | 입력 가장자리에 0 추가. 출력 크기 유지 |
| **Max Pooling** | 영역에서 최댓값만 남기기 | 크기 축소 + 위치 불변성 |
| **1×1 Conv** | 채널별 가중합 | 공간은 유지, 채널 수 조절 |
| **Depthwise Separable** | 분업: 공간 먼저, 채널 나중 | 표준 conv 대비 ~8배 효율적 |

**1×1 Convolution이 중요한 이유**:
```python
# 256채널 → 64채널로 줄이기 (bottleneck)
# 공간(H, W)은 건드리지 않고 채널 수만 조절
conv1x1 = nn.Conv2d(256, 64, kernel_size=1)
```
- 역할: 채널 축소/확장, 비선형성 추가, 연산량 감소
- Inception, ResNet Bottleneck에서 핵심

→ "남에게 설명한다면: Stride는 건너뛰기, Padding은 여백 추가, Pooling은 요약, 1×1 Conv는 채널 수 조절이다."

### ⚡ 핵심 요약
- **핵심**: 출력 크기 공식 `(H + 2P - K) / S + 1`을 알면 네트워크 설계 가능
- **주의**: Depthwise Separable Conv = MobileNet의 핵심. 모바일/엣지 배포에 필수

### 🔑 결국 뭐가 중요한가
1. 출력 크기 계산 = CNN 아키텍처 설계의 기본기
2. 1×1 Conv = "싸고 효과적인 채널 변환기". 거의 모든 현대 CNN에서 사용
3. Depthwise Separable = 효율적 추론의 핵심 (MobileNet, EfficientNet)

## 11-1. RNN / LSTM / GRU

### 🎯 한 줄 결론
순서가 중요한 데이터를 처리하기 위해, **이전 정보를 기억하면서** 다음 입력을 처리하는 구조다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

스트리밍 로그 처리 비유:

**RNN = 상태를 유지하는 로그 프로세서**
```python
class LogProcessor:
    state = {}  # 이전까지의 정보 (hidden state)

    def process(self, new_log):
        self.state = update(self.state, new_log)  # 기존 상태 + 새 로그
        return analyze(self.state)
```
- 문제: 오래된 로그의 정보가 점점 희석됨 (vanishing gradient)

**LSTM = 장기 저장소가 추가된 프로세서**
```python
class LSTMProcessor:
    short_term = {}   # 단기 기억 (hidden state)
    long_term = {}    # 장기 기억 (cell state) ← 핵심 추가!

    def process(self, new_log):
        # 3가지 결정
        forget = decide_what_to_forget(self.short_term, new_log)   # Forget Gate
        save = decide_what_to_save(self.short_term, new_log)       # Input Gate
        output = decide_what_to_output(self.short_term, new_log)   # Output Gate

        self.long_term = forget * self.long_term + save * new_info
        self.short_term = output * tanh(self.long_term)
```
- 장기 기억(cell state)이 컨베이어 벨트처럼 정보를 먼 거리까지 전달

**GRU = LSTM의 경량화 버전**
- 게이트 3개(LSTM) → 2개(GRU): Update Gate + Reset Gate
- Cell state와 hidden state를 통합
- 파라미터 25% 적음, 성능은 비슷

→ "남에게 설명한다면: RNN은 로그를 순서대로 처리하면서 상태를 유지하는 것이고, LSTM은 장기 저장소를 추가해서 오래된 정보도 잊지 않는 것이다."

### ⚡ 핵심 요약
- **핵심**: LSTM의 Cell State = 정보가 거의 변형 없이 흐르는 고속도로 → 장기 의존성 학습
- **주의**: Transformer 등장 후 RNN 계열은 많이 대체되었지만, 실시간 스트리밍 등에서는 여전히 유용

### 🔑 결국 뭐가 중요한가
1. RNN = 순서 있는 데이터 처리의 기본. 하지만 장기 기억 약함
2. LSTM = Forget/Input/Output 게이트로 장기 기억 관리. 핵심은 Cell State
3. 현재는 대부분 Transformer로 대체. 하지만 RNN의 개념은 여전히 중요

## 11-2. Attention / Self-Attention / Transformer

### 🎯 한 줄 결론
입력의 **어느 부분에 집중할지**를 동적으로 결정하는 메커니즘이며, Transformer는 이것만으로 만든 아키텍처다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

**Attention = DB 쿼리와 같은 원리**

```sql
SELECT value FROM data WHERE key LIKE '%query%'
-- Query: 내가 찾고 싶은 것
-- Key: 각 데이터가 "나는 이런 정보야"라고 태그한 것
-- Value: 실제 데이터
```

자연어 번역 예시 "나는 학교에 간다" → "I go to school":
- "I"를 생성할 때 → "나는"에 집중 (높은 attention weight)
- "school"을 생성할 때 → "학교"에 집중
- 각 출력 단어가 입력의 **다른 부분에 다른 가중치**로 집중

**Self-Attention = 문장 내부에서 자기 자신과의 관계 파악**

"The cat sat on the mat because **it** was tired"에서:
- "it"이 "cat"을 가리키는지 "mat"을 가리키는지 파악
- 문장 내 **모든 단어쌍의 관련성**을 계산

**Transformer = Attention만으로 만든 아키텍처**
- RNN 없이 **병렬 처리** 가능 → 훈련 속도 획기적 향상
- 핵심 구성: Multi-Head Attention + Feed-Forward Network + Residual + Layer Norm

```
입력 → [Multi-Head Self-Attention] → [Add & Norm] → [Feed-Forward] → [Add & Norm] → 출력
                                         ↑ skip connection                ↑ skip connection
```

**Multi-Head Attention = 여러 관점에서 동시에 보기**
```python
# Head 1: 문법적 관계에 집중
# Head 2: 의미적 관계에 집중
# Head 3: 위치적 관계에 집중
# → 결과를 concat해서 합침
```

→ "남에게 설명한다면: Attention은 DB 쿼리처럼 Query로 관련된 Key를 찾아 Value를 가져오는 것이고, Transformer는 이 메커니즘만으로 전체 모델을 만든 것이다."

**[중급 — 어떻게 작동하는가]**

Attention 계산:
```python
# 1. Query, Key, Value 생성 (입력에 서로 다른 가중치 행렬 곱)
Q = input @ W_Q  # "내가 뭘 찾는지"
K = input @ W_K  # "내가 뭘 갖고 있는지"
V = input @ W_V  # "내 실제 정보"

# 2. 유사도 계산 (Q와 K의 내적)
scores = Q @ K.T / sqrt(d_k)  # 스케일링

# 3. 확률로 변환
weights = softmax(scores)  # 각 위치에 얼마나 집중할지

# 4. 가중 평균
output = weights @ V  # 집중도에 따라 정보 수집
```

`sqrt(d_k)`로 나누는 이유: 차원이 클수록 내적 값이 커져서 softmax가 극단적이 됨 → 스케일링으로 방지

**Positional Encoding**: Transformer는 순서를 모르므로, 위치 정보를 수학적으로 더해줌
- sin/cos 함수 사용 → 상대적 위치 관계를 인코딩

→ "남에게 설명한다면: Q@K로 유사도 구하고, softmax로 확률 만들고, V에 가중 평균 취하는 게 전부다. DB의 JOIN + GROUP BY와 비슷하다."

### ⚡ 핵심 요약
- **핵심**: Attention은 O(n²) 복잡도 (모든 쌍 계산). 긴 시퀀스에서 비용이 큼
- **어디에 쓰이는가**: GPT, BERT, Vision Transformer(ViT) 등 현대 AI의 거의 모든 곳
- **주의**: "Attention is All You Need" = 2017년 논문 제목이자 딥러닝 역사의 전환점

### 🔑 결국 뭐가 중요한가
1. Attention = Query-Key-Value 메커니즘. DB 쿼리와 같은 원리
2. Transformer = Attention + Skip Connection + Layer Norm. 현대 AI의 기본 뼈대
3. 병렬 처리 가능 → RNN보다 훈련이 훨씬 빠름 → 대규모 모델의 시대를 열음

## 12-1. Transfer Learning / Fine-tuning

### 🎯 한 줄 결론

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

Docker 이미지 비유:

- **Fine-tuning** = base 이미지 위에 내 앱 레이어 추가

| 전략 | 비유 | 언제 사용 |
|------|------|----------|

| Linear Probing | 마지막 레이어만 교체 | 데이터 매우 적을 때 |

→ "남에게 설명한다면: Docker base 이미지를 재활용하듯, 큰 데이터로 학습된 모델을 가져다가 내 데이터로 살짝만 조정하는 것이다."

### ⚡ 핵심 요약
- **핵심**: 현대 딥러닝의 사실상 표준 워크플로우. 처음부터 학습하는 경우는 드물다
- **어디에 쓰이는가**: BERT→NLP 태스크, ImageNet→의료 이미지, GPT→ChatGPT

### 🔑 결국 뭐가 중요한가
1. Pre-training + Fine-tuning = 현대 딥러닝의 기본 패러다임
2. 데이터가 적을수록 pre-trained 모델의 가치가 높아짐
3. 학습률 차등 설정: 하위 층은 작게, 상위 층은 크게

## 12-2. Self-Supervised Learning / Contrastive Learning

### 🎯 한 줄 결론
레이블 없이 **데이터 자체에서 학습 과제를 만들어** 유용한 표현을 배우는 방법이다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

레이블링 비용 문제:
- ImageNet 레이블링: 약 2500만 달러 소요
- 하지만 인터넷에는 레이블 없는 이미지/텍스트가 수십억 개

해결: 데이터 자체에서 "구실 과제(pretext task)"를 만들자!

**예시들**:
| 분야 | Pretext Task | 비유 |
|------|-------------|------|
| NLP (BERT) | 문장의 단어를 가리고 맞추기 | 빈칸 채우기 시험 |
| NLP (GPT) | 다음 단어 예측 | 문장 이어쓰기 |
| Vision | 이미지 회전 각도 맞추기 | 퍼즐 맞추기 |
| Vision | 같은 이미지의 다른 augmentation끼리 가깝게 | 같은 사람의 다른 사진 매칭 |

**Contrastive Learning (대조 학습)**:
```python
# 같은 이미지의 두 가지 변형 → 가깝게 (positive pair)
# 다른 이미지의 변형 → 멀게 (negative pair)
loss = -log(sim(augmented_v1, augmented_v2) / sum_of_all_pairs)
```

→ "남에게 설명한다면: 정답 없이도, 데이터를 변형해서 '이것과 저것이 같은지 다른지' 판단하는 과제를 만들어 학습시킨다."

### ⚡ 핵심 요약
- **핵심**: GPT, BERT, CLIP 등 현대 초대형 모델의 핵심 학습 방법
- **연구 포인트**: "좋은 pretext task = 좋은 표현 학습"이므로, 어떤 과제를 설계하느냐가 핵심

### 🔑 결국 뭐가 중요한가
1. 레이블 없는 대규모 데이터 활용 = 현대 AI의 핵심 돌파구
2. GPT = 다음 토큰 예측, BERT = 마스크 토큰 예측. 둘 다 self-supervised
3. Contrastive Learning = "같은 것은 가깝게, 다른 것은 멀게"

## 12-3. GAN / VAE / Diffusion Model

### 🎯 한 줄 결론
데이터와 비슷한 **새로운 데이터를 생성**하는 세 가지 대표 접근법이다.

### 📖 단계별 설명

**[입문 — 왜 존재하는가]**

**GAN (Generative Adversarial Network)** — 위조범 vs 감식관 게임:
- 생성자(Generator): 가짜 데이터 생성 → 진짜처럼 만드는 것이 목표
- 판별자(Discriminator): 진짜/가짜 구별 → 정확히 구별하는 것이 목표
- 둘이 경쟁하면서 둘 다 실력이 올라감
- 비유: 위조지폐범과 은행 감식관이 서로 실력을 키우는 것

**VAE (Variational Autoencoder)** — 압축 후 복원:
- 데이터를 확률 분포로 압축(인코딩) → 다시 복원(디코딩)
- 비유: 파일을 zip으로 압축했다가 다시 풀기. 압축 공간에서 새로운 파일 생성 가능
- 장점: 생성의 다양성 조절 가능, 의미 있는 잠재 공간(latent space)

**Diffusion Model** — 노이즈 제거:
- 순방향: 데이터에 노이즈를 점점 추가해서 완전한 잡음으로 만듦
- 역방향: 잡음에서 노이즈를 단계별로 제거해서 깨끗한 데이터 생성
- 비유: 깨끗한 사진에 먼지를 뿌리는 과정을 학습한 후, 먼지투성이 사진을 복원
- Stable Diffusion, DALL-E 등의 기반 기술

→ "남에게 설명한다면: GAN은 위조범-감식관 경쟁, VAE는 압축-복원, Diffusion은 노이즈 추가-제거다. 모두 새로운 데이터를 만드는 방법이다."

### ⚡ 핵심 요약
| 모델 | 장점 | 단점 |
|------|------|------|
| GAN | 생성 품질 높음 | 학습 불안정, 모드 붕괴 |
| VAE | 안정적 학습, 잠재공간 해석 가능 | 생성 품질 상대적으로 낮음 |
| Diffusion | 최고 품질, 안정적 학습 | 생성 속도 느림 (반복 샘플링) |

### 🔑 결국 뭐가 중요한가
1. 현재 이미지 생성의 최강자 = Diffusion Model
2. GAN = 학습이 어렵지만 빠른 생성. 실시간 응용에 유리
3. VAE = 잠재공간이 의미 있어서 편집/보간(interpolation)에 좋음

# 부록: 자주 헷갈리는 용어 쌍

| 쌍 | 차이 |
|-----|------|
| **Parameter vs Hyperparameter** | Parameter = 모델이 학습하는 값(가중치). Hyperparameter = 사람이 설정하는 값(학습률, 배치크기) |
| **Epoch vs Iteration vs Batch** | Epoch = 전체 데이터 1회 학습. Batch = 한 번에 처리하는 데이터 묶음. Iteration = 배치 1개 처리 |
| **Training vs Validation vs Test** | Training = 학습용. Validation = 튜닝용(모의고사). Test = 최종 평가용(실제 시험, 한 번만) |
| **Overfitting vs Underfitting** | Overfitting = 훈련만 잘하고 실전 못함. Underfitting = 훈련도 못함 |
| **Bias(편향) vs Bias(편향항 b)** | Bias-Variance의 Bias = 모델의 단순함에서 오는 에러. 신경망의 bias b = 절편 |
| **Normalization vs Regularization** | Normalization = 데이터/활성화를 정규화(BatchNorm 등). Regularization = 과적합 방지(L2, Dropout 등) |
| **Convolution vs Cross-Correlation** | 수학적 Convolution = 커널 뒤집기. CNN의 "Convolution" = 실제로는 Cross-Correlation (뒤집지 않음). 학습하므로 결과 동일 |
| **Equivariance vs Invariance** | Equivariance = 입력이 변하면 출력도 같이 변함. Invariance = 입력이 변해도 출력이 안 변함 |
